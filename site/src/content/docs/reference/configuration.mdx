NMSh avoids merging dotfiles, creating wrapper scripts, or silently modifying your environment. Everything about the frontend is configured through its internal UI, which serializes safely to a well-known JSON file.

## Configuration File

The configuration file is typically located at:
```text
~/.gemini/notMyShell/config.json
```
_Do not edit this file by hand._ It is structurally managed by the `/settings` UI and various configuration wizards (like Theme Studio and tmux Config Studio). Use `nmsh config path` to verify its location on your system.

## Exporting & Importing

Configuration is strictly typed and exportable. An export never contains sensitive machine state (credentials, history paths, transcripts).

You can export your configuration to share with others, use on another machine, or back up:
```bash
nmsh config export --output my-nmsh-config.json
```

Importing configuration previews the exact changes (additions, modifications, removals) before applying:
```bash
nmsh config import my-nmsh-config.json
```

### Portable Categories

You can export or import specific slices of configuration using `--categories`. The available categories are:
- `appearance`: UI Chrome, Transcript formatting, Syntax highlighting, Motion/Animations.
- `themes`: Theme Bridge settings, Catppuccin accent, Theme Palette selections, and Custom Themes.
- `prompt`: Prompt Style, Connector Geometry, Glyphs, and Context Module layout.
- `behavior`: Welcome provider, Fold Policy, Update checks, and Live Session startup rules.
- `providers`: Backends for suggestions, history, pickers, directory navigation, and tools.
- `terminal`: Terminal Title injection and Open-with integration.
- `agents`: Managed Agent profiles and Understanding settings.
- `status`: Status Strip modules and visibility.

Example: `nmsh config export --categories appearance,themes --output my-theme.json`

## Settings Reference

The `/settings` panel organizes these options into logical sections. Here are the core settings you can control:

### Appearance & UI
- **Motion & Animation**: Toggle animations for command execution, UI transitions, and composer docking. (Default: ON, respects OS `prefers-reduced-motion`).
- **Composer Position**: `Bottom`, `Top`, or `Flow`. Flow places the composer immediately after the previous command's output.
- **Transcript Presentation**: `Normal` (standard terminal log) or `Chat` (bubble/card style).
- **Vibrance**: `Standard` or `Muted`. Muted reduces the saturation of semantic highlights and prompt elements.
- **Glyph Style**: `Nerd` (requires a Nerd Font) or `Safe` (uses standard Unicode fallback characters).

### Behavior
- **Paste Preview**: Controls how multiline clipboard content is handled. `Smart` folds massive pastes but lets you edit them in the composer before execution.
- **Output Folding**: `Smart` folds massive logs (like build spam) automatically, keeping the transcript readable while preserving the raw output under `Ctrl+O`.
- **Live Session Startup**: `Ask`, `Always`, or `Never`. Controls what happens when you launch NMSh and there are existing detached sessions running.

### Environment Providers
NMSh delegates heavy lifting to the best available tools, defaulting to built-in Native providers.
- **Suggestions Provider**: `nmsh` (Native), `fig`, `carapace`, or `zsh-autosuggestions`.
- **History Provider**: `native` (SQLite structured history), `zsh`, `bash`, `fish`, or `atuin`.
- **Picker Provider**: `native`, `fzf`, or `peco`.

### Terminal Integration
- **Terminal Title**: `off`, `minimal`, `verbose`. When on, NMSh manages the window/tab title using OSC 0/2 escapes, restoring the host's previous title when you exit.
- **Open With**: Integration for opening files or links. `auto`, `open`, `xdg-open`, or host-specific actions (e.g. `ghostty`).

## Themes and Context Packs

**Themes** are stored alongside configuration but managed via the Theme Studio (`/theme`). They define color palettes for the transcript, composer, and semantic highlighters.

**Context Packs** (for the Context Engine) are declarative bundles of modules. They are installed to `~/.gemini/notMyShell/context-packs/` and managed using the `nmsh packs` command or `/prompt` UI.

## Ownership Ledger

NMSh keeps an internal **Ownership Ledger** detailing exactly what modifications it has made to your host system (e.g., adding Homebrew taps, installing packages via `/tools`, editing `~/.zshrc` block markers).

The ledger can be viewed in `/settings > Advanced > Ownership Ledger`. This ensures NMSh can safely revert its own changes during `nmsh uninstall` without breaking your manual configuration.
