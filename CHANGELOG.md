# Changelog

All notable changes to NMSh are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). Notable user-visible changes are added under [Unreleased] as they land; see [CONTRIBUTING.md](CONTRIBUTING.md#changelog).

## [Unreleased]

### Added

- **Console for the browser preview** ([#466](https://github.com/raiseCatError/notMyShell/issues/466); [design](docs/design/document-workspace.md#console-runtime-diagnostics-of-the-browser-preview)). In the Chromium preview of a Markdown or HTML document, **`C`** lists what the page itself reported for the document now loaded: script exceptions, `console` errors, warnings and messages, failed loads and HTTP errors, Content Security Policy refusals and requests NMSh refused. It works like Problems — newest first, Tab filters by severity, typing searches, Shift+↑↓ marks, Del clears, Ctrl+C shows exactly what would be copied before copying — and Enter goes to the line in the file when that is certain (an HTML document unchanged since the page loaded); otherwise it says why. The Console only reads: it never turns scripts or the network on (with scripts off, only loading and policy messages appear), accepts no expressions, and ignores `/browser` pages and the Mermaid renderer. Entries stay in memory for the current load, bounded, with the preview's address, query values, tokens and likely secrets redacted before they are kept. The status line counts errors and warnings.
- **`/doctor` reports document rendering** ([#462](https://github.com/raiseCatError/notMyShell/issues/462)). A Documents section names the Chrome or Chromium the previews would use (its version once a browser surface has checked it this session, and whether it is running), the Mermaid it found (path, version, a warning for a major version other than the tested 12), the Mermaid setting and, when diagrams would not be drawn, why. Nothing is launched and the Mermaid bundle is not read, so it says what was found, not that drawing works.
- **Mermaid diagrams in Markdown** ([#462](https://github.com/raiseCatError/notMyShell/issues/462); [design](docs/design/diagrams.md)). A ```` ```mermaid ```` fence is drawn as a real diagram — flowcharts, sequence, class, state, ER, Gantt, pie, journey, git graph, mind map, timeline, quadrant, XY, requirement, Sankey, block and C4 diagrams — in Preview (NMSh's renderer and the Chromium preview), Split's preview pane, the viewer and Hybrid's inactive blocks, with the image backend your terminal supports (Kitty graphics, iTerm2, Sixel, or character art); `i` opens it in the image viewer to zoom and pan. NMSh uses the Mermaid you installed (`npm install -g mermaid`, or `NMSH_MERMAID`) inside the real browser it already drives, and downloads nothing. The page that draws runs no document script, loads nothing from the network or disk and returns only pixels; Mermaid's security settings are locked against directives. Settings → General → **Mermaid diagrams**: *On request* (default: press `D`, or F1 › Diagrams while editing — opening a document never starts a browser), *Automatic*, or *Off*. The fence stays the source: in Hybrid the block under the caret is its exact text, edits are drawn after a pause, and anything not drawn (not asked yet, no browser or Mermaid, a syntax error, too large, a timeout) shows the fence as written with `(diagram not drawn: reason)`. Drawings are cached by content and theme, bounded in number, bytes and time, and the renderer page closes when no document shows a diagram.
- **Hybrid Markdown editing** ([#460](https://github.com/raiseCatError/notMyShell/issues/460)). **F3** in a Markdown document (or `H` from the read-only views) shows it *rendered* — headings, emphasis, links, lists, tables, quotes, code — except for the block your caret (or selection) is in, which shows its exact Markdown source and is fully editable. Move on and it renders again. It is another presentation of the same buffer: every key is the editor's (letters always type; snippets, list/table helpers, undo/redo, hunk review, recovery drafts and Save As all work as in the source editor), the caret lives in source positions, and switching views never changes the text. The smallest safe block is revealed — the whole list for a nested item, the whole table, the whole fence — and a selection shows every block it touches as source. The view is anchored to a source line, so revealing a block does not move what is above it. F3 again returns to the source editor; in the split view (F2) F3 switches the text pane between source and hybrid. Limits: Markdown files only (not HTML); images appear as `[image: alt]`; Up/Down move by source line; pointer input is not handled.
- **Expandable `<details>`** ([#462](https://github.com/raiseCatError/notMyShell/issues/462)). The native Markdown/HTML viewer now shows `<details><summary>…</summary>…</details>` as a disclosure: `▸ Summary` when closed (hiding its content), `▾ Summary` with the content indented when open — in the rendered view, the preview, the split's preview pane and the hybrid view. GitHub-style details, with a blank line and Markdown inside and `</details>` in a later block, are understood (nested ones too); the `open` attribute sets the starting state. **`z`** toggles the summary at or below the top of the screen, **`Z`** all summaries in view; choices are kept by summary text, survive scrolling, resizing and edits above, and never change the file. Scripts, handlers and unknown tags in a details block are inert text. Not yet: pointer clicks (the viewer has no pointer support), and toggling inside the hybrid view (it shows each details as written: closed unless `open`).
- **Math in Markdown** ([#462](https://github.com/raiseCatError/notMyShell/issues/462)). `$…$` (GitHub's rules: no space inside the dollars, not before a digit) and display `$$…$$` / ```` ```math ```` render as typeset math in the viewer, preview, split and hybrid view, offline and without a browser: real stacked fractions with a bar, roots, super- and subscripts (Unicode where every character has one, an unambiguous `x^(…)` form otherwise, placed in two dimensions in display), `∑ ∏ ∫` with limits, Greek letters, operators and relations, `\left…\right` stretched delimiters, `matrix`/`pmatrix`/`bmatrix`/`vmatrix`/`cases` and `\text`. It is a defined subset, not full LaTeX: anything outside it (unknown commands, too large, too wide, a fraction that does not fit one row inline) stays as its source text with a dim `(not rendered: reason)`, never a guess. Source is preserved exactly (the editor and `/copy` are unchanged), Safe Glyphs draw with plain ASCII, and formulas are limited in size, depth and rows. Rendering through KaTeX in the optional browser is not part of this slice.
- **Problems: offline static diagnostics** ([#466](https://github.com/raiseCatError/notMyShell/issues/466)). In a Markdown, HTML or CSS document, **F1 then `e`** (the snippet palette's *Problems…* in HTML files; **F1** in a CSS file; **`P`** in the read-only views and the split's preview pane) lists what is wrong: ✖ errors, ▲ warnings, ℹ notes and `?` things that cannot be checked. Markdown: links to files that do not exist, `#fragments` with no heading or id, missing images, images without alt text, undefined `[text][ref]` references and footnotes, unused footnotes, repeated headings. HTML: missing images, stylesheets and scripts, `<img>` without `alt`, form controls without a label, duplicate ids, unresolved `#fragments`, unclosed or unexpected tags. CSS: missing `url()` assets and unbalanced braces. Type to search, Tab filters (all, problems, errors), Enter jumps to the exact text and selects it (Back returns), Del dismisses one, Ctrl+R checks again. Checking starts when you first open Problems, follows the text (typing, undo, snippets, restored drafts, a merge) after a short pause, drops results for text that has since changed, and counts show in the editor's status row. Everything is offline: external URLs are counted, never fetched; no script, style or command is run; files are only looked at (never read except another Markdown file's headings, 256 KiB at most) and only inside the document's project (a path that leaves it, by `..` or a symlink, is reported as not checked); nothing is written. Browser-console diagnostics are a later, separate step.
- **Footnote renumbering** ([#463](https://github.com/raiseCatError/notMyShell/issues/463)). *Renumber footnotes* in the snippet palette (F1, then `/` in a Markdown file) numbers the footnotes 1, 2, 3… in the order they are first referenced and updates each definition to match, as one undo step. Named footnotes (`[^note]`), escaped references, code spans and fenced code are left alone; a definition nobody references keeps its number unless a renumbered footnote needs it.
- **Split view for Markdown and HTML documents** ([#461](https://github.com/raiseCatError/notMyShell/issues/461)). **F2** (or `s` in the read-only views) in the document workspace shows the editor beside NMSh's own preview of the *same* buffer: the text on the left, the rendered document on the right, updated as you type, without saving. The preview follows the caret to its block (`l` in the preview pane turns that off), **Ctrl+O** moves between the panes, `x` swaps the sides and `<` `>` change their widths (30–70%). Only the text pane is editable; keys typed while the preview has the focus never reach the text. The preview pane has its own find (`/`) and heading prompt (`#`). Below 100 columns only the focused pane is shown at full width, and widening the terminal brings the split back. Esc leaves for the read-only source view with your unsaved text kept; F2 again returns to editing. The browser-quality preview is not used in the split; the pane is NMSh's renderer. Mouse input in the split is not handled yet.
- **Heading navigation** ([#462](https://github.com/raiseCatError/notMyShell/issues/462), first slice). In a Markdown or HTML document, **`#`** in the viewer or workspace opens a heading prompt: type to narrow, Up/Down choose, Enter jumps (source or rendered view, any width) and **Backspace** goes back to where you were. In the editor, F1 then `h` (or *Go to heading…* in the snippet palette) lists the headings with their depth; `j` / *Back* returns to the caret position you left, even after edits. `/view README.md#install` opens the file at that heading. Anchors follow GitHub's rules (lower-case, punctuation dropped, `-1`, `-2` for repeats; raw HTML headings listed without an anchor); Jekyll/Kramdown ids are different and are not implemented (see the [architecture note](docs/architecture/document-source-map.md)). Underneath, every parsed Markdown block now knows its source lines and every rendered row its block's line, the shared map the coming split view and hybrid editing build on.
- **`/playground`: an unsaved Markdown or HTML document** ([#468](https://github.com/raiseCatError/notMyShell/issues/468), second slice). `/playground md`, `/playground html`, or `/playground` to choose, opens an editable scratch document in the document workspace at once — type, switch between source, edit and preview with the usual keys, and use the snippets. Nothing is saved for you: **Ctrl+S asks for a file name** (Save As creates a new file with the same checked save as `/edit` and never replaces an existing one), and closing with unsaved text asks Save As, Discard or Keep editing. If NMSh or the terminal dies, the text is kept as a private draft and `/playground recover` brings it back. The preview is NMSh's own renderer: no browser process, no folder served, scripts and network stay off. Split view arrives with [#461](https://github.com/raiseCatError/notMyShell/issues/461).
- **Snippets in `/edit`** ([#468](https://github.com/raiseCatError/notMyShell/issues/468), first slice). In a Markdown or HTML file, **F1** (Markdown: F1 then `/`) opens a searchable palette of built-in templates — headings, tables, task lists, fenced code, block quotes, footnotes, Mermaid and math blocks (inserted as source text), an HTML page skeleton, semantic sections, lists, tables, links and images — together with the editing actions that already exist. Type to filter, Enter inserts. A snippet is plain text inserted as one undoable edit; its placeholders are selected one by one with **Tab / Shift+Tab** for as long as you are inside it, **Esc** or moving away ends that without touching the text, and Tab is an ordinary tab everywhere else. Block templates start on their own line, wrap a selection where it makes sense, and follow the line's indentation. Nothing is executed, fetched or installed.
- **Review changes made on disk while you edit** ([#463](https://github.com/raiseCatError/notMyShell/issues/463), third slice). When saving finds the file changed by something else, the conflict choice now includes **Review changes** (`v`). It merges three versions — the file as you opened or last saved it, your unsaved text and the file now on disk — and lists the hunks. Changes only the disk made default to the disk's version (`m` keeps yours instead); text you both changed, or changes that touch each other, are conflicts that stay undecided until you pick yours (`m`), the file's (`t`), both (`b`) or the original (`o`). `n`/`p` move between hunks, `c` jumps to the next conflict, `r` previews the result, `z` takes back a decision, Esc closes without changing anything. **Enter** applies the result to the editor as one undoable edit after re-reading the file (if it changed again, the review starts over); nothing is written to the file until you save, and the save re-checks it as always. A deleted file offers Save anyway only. Very different files (more than 1,500 edits from the version you opened) are one coarse conflict, never a guess.
- **Table editing in `/edit`** ([#463](https://github.com/raiseCatError/notMyShell/issues/463), second slice). In a GFM table in a Markdown file, **Tab / Shift+Tab** move between cells and select the cell's text (the delimiter row is skipped; outside a table Tab is a tab as before), the status line names the row and column, and **F1** adds the table actions: add a row below, delete a row, add a column to the right, delete a column, cycle the column's alignment. Each edits only the table rows it changes, keeps your spacing, outer pipes and alignment colons, and is one undo step; the table is never regenerated or re-padded.
- **Markdown editing helpers in `/edit`** ([#463](https://github.com/raiseCatError/notMyShell/issues/463), first slice; Markdown files only). **Enter** continues a bullet, numbered or task list (same marker and indentation, next number, unchecked box) and splits an item at the caret; on an empty item it ends the list (a nested one steps out a level). **Tab / Shift+Tab** on list items indent or outdent the item with its children (selected items together); elsewhere Tab is a tab as before. **F1** opens the Markdown actions: toggle a task checkbox, renumber the list at the caret, insert a link or image around the selection, wrap the selection in bold, italic, code or strikethrough (again to unwrap). Every action changes only the lines it names and is one undo step; text is never reflowed or regenerated.
- **Crash recovery for `/edit` and the document workspace** ([#469](https://github.com/raiseCatError/notMyShell/issues/469)). Unsaved changes are written, a moment after you stop typing, to a private draft in NMSh's data folder (`recovery/`, mode 0700; files 0600). After a crash, a kill or a closed window, opening the file offers **Restore draft**, **Compare with file**, **Discard draft** or **Keep for later**; nothing is applied until you choose, a draft made from an older version of the file says so, and the file itself is only ever written by the editor's normal checked save (which also retires the draft). Two windows on one file keep separate drafts, and a draft of a window that is still running is never offered. Drafts are bounded (2 MiB each, 50 in all, 30 days) and are never sent anywhere.

## [0.23.0] - 2026-10-21 — Vespyr Arcade

The Arcade grows from five games to 33, and it can now be played while a command keeps running.

### Added

- **The Vespyr Arcade grows to 33 games** ([#481](https://github.com/raiseCatError/notMyShell/issues/481); trackers [#474](https://github.com/raiseCatError/notMyShell/issues/474)-[#480](https://github.com/raiseCatError/notMyShell/issues/480)). This is the unreleased v0.23.0 work: nothing here is released, and it has no date. `/game <name>` opens any game by id or alias (102 names, all unique):
  - **Runners:** Vespyr Run, Flight, Dash, **Vespyr Leap** (bounce from platform to platform; sliding and crumbling platforms, springs), **Alley Sprint** (three lanes), **Kitten Parade** (grow a crowd through five levels with battles and bosses) and **Vespyr Rover** (a physics hill-climb with fuel, tilt and flips).
  - **Arcade and reflex:** **Tail Chase** (Snake with three modes), **Purr Pong**, **Brickfall**, **Maze Prowler**, **Cat Tower**, **Vespyr Bullseye**, **Color Orbit** and **Glass Rush**.
  - **Physics and falling:** **Vespyr Pinball** (drop targets, spinner, ramp), **Catapult Cats**, **Yarn Drop**, **Sandfall** and **Merge 2048**, **Treat Match**.
  - **Logic:** Classic Sudoku, Vespyr Queens, **Minefield** (classic and **Hex Minefield**), **Tile Slide**, **Box Escape**, **Ice Paws**, **Moonjars**, **Yarn Lines**, **Circuit** and **Cat Fleet** (Battleship).
  - **Words and typing:** **Purrword** (a five-letter word in six, daily and practice) and **Driftkeys** (type drifting phrases; the keys never reach the shell).
  Every game is offline, deterministic where it has a seed, and keeps its own local records. The per-game list with controls is in [the status ledger](docs/development/arcade-expansion-status.md).
- **Play while a command runs** ([design](docs/design/arcade-background-work.md)). Ctrl+T (NMSh's own key, never sent to a program), or typing `/games` (`/arcade`, `/game`, `/game <id>`) and accepting the inline offer `Open Arcade while the command runs? Enter Open · Esc Cancel`, opens the Arcade over a running command that is not waiting for input. The command, its session and its output are untouched and keep being recorded; Ctrl+C leaves the Arcade, never the command. Nothing typed in a game reaches the shell, the composer or the queue, and a command held for approval stays held. Opening is refused unless NMSh's own evidence says the command is not reading the keyboard; a question from the program pauses the game and says so, and a program that takes the terminal closes the Arcade at once.
- **A shared Arcade header**: the shell-side work at the top-left (the foreground command, the queue, `/bg` and Ask tasks, `/track` watchers with their schedule, and commands that just finished; up to three rows and `+ N more activities`) and a persistent notification banner at the top-right with an accent bar in your theme's color (`✓ Command completed`, `npm run build · 42.0s · exit 0`; failures, queue finished / waiting for approval / paused, input needed). The banner stays until something newer replaces it; a failure is not hidden by later successes; `n` (or Notifications in the pause menu) shows the last 24 events. Labels are program words only, never arguments or output. Reduced Motion, NO_COLOR and Safe Glyphs keep every meaning in words and glyphs.
- **Boards that are square on screen.** Sudoku, Merge 2048, Minefield, Ice Paws, Yarn Lines, Moonjars and Treat Match size their cells from the terminal's cell aspect (assumed 2:1), with mouse hit-testing on the same layout.
- **Hex Minefield**: Minefield on a six-neighbour hexagonal board with its own best times. It is drawn as nesting hexagons where they fit (Large at 80x24); where they cannot be drawn the title says "staggered tiles", and NO_COLOR and Safe Glyphs always use staggered tiles. Classic stays the default.

### Changed

- **Vespyr Arcade is a full-screen application** ([design](docs/design/arcade-expansion.md), [#474](https://github.com/raiseCatError/notMyShell/issues/474)). `/games` now takes the whole terminal: no banner, Status Strip, sidebar, transcript or composer around it, the shell's size unchanged, and the ordinary screen back exactly on exit. It rises in and recedes (none under Reduced Motion, Effects Off or without color). The hub is a library grouped by category with Favorites (`f`), Recently played, search (`/`), Tab between groups, the mouse wheel and clicks, and a live preview of the highlighted game; it remembers the game you played last. Narrow terminals show one game at a time. A game fills the screen with one row of controls; Esc opens a pause sheet with How to play, and finishing plays the game's own celebration before a results card that counts the score up.
- **Vespyr Doku is now Vespyr Queens** (`/game queens`; `vespyr-doku` and `doku` still work). Scores and a puzzle in progress move with it. The arcade's data file becomes version 2 (up to 64 games); the first write keeps the old file as `arcade.json.v1-backup`, and an older NMSh shows a version 2 file read-only instead of rewriting it.
- **Classic Sudoku redesign**: boxes on raised plates separated by dark channels, cells as tiles that never merge, givens and your digits in different colors and weights, distinct highlights for the cursor, its row, column and box, matching digits and clashes, positional notes, a remaining-digit counter, a light sweeping along each finished row, column and box, and a wave across the solved board.
- **Vespyr Queens redesign**: regions as solid shapes in clearly different colors with dark channels between them, the region letter once per region instead of in every cell, cats on dark badges, a pixel exclusion mark, finished regions checked, and a hop wave across the cats when solved.
- **Vespyr Run, Flight and Dash have their own worlds**: a dusk meadow with a setting sun and rising moon, a moonlit city of libraries with lit windows, and a neon stage with a striped sun that pulses on the beat. Obstacles use colors that never match Vespyr, and Dash's spikes keep one hazard color in every phase.

### Fixed

- **Color Orbit is playable.** A tap is now a classic fixed hop (about a quarter of a ring) that never stacks, with steady gravity; prisms are spaced so a larger ring can no longer recolor the ball mid-crossing. Seeded tests with human tap intervals pass; mashing and idling still lose.
- **Arcade fixes found in review** (unreleased work only; nothing in v0.22.0 changes): Moonjars' "proven" target was one pour too long for 21 of 400 decks and its startup search could stall; Treat Match's hint key was dead, tiles drew over the progress row at small sizes and a reshuffle was silent; Merge 2048's +N popup covered the title row; Pinball's ready text was unreadable; Rover's tilt response was too weak for a 6-8 taps/s driver to flip off real jumps and its HUD clipped at 28 columns; Kitten Parade's gates drew `?` in Safe Glyphs and a full crowd overflowed its lane; Vespyr Leap's fall limit tied to screen height made deaths unavoidable on short terminals (8% of late bounces at 34 rows, 64% at 12).

### How the Arcade work was verified

- **Automated, on the branch tip before commit:** 559 arcade tests (558 pass, 1 todo), `tsc` clean, the fast suite 68/68, and a smoke render of all 33 games at 100x34, at 40x16 with Reduced Motion and at 28x12 with NO_COLOR and Safe Glyphs. `tests/arcadeAll.test.ts` checks every game for metadata, garbage records, resize, dispose, pause, key ownership, previews, v0.22 save migration and that games use no network, child process, filesystem or timers.
- **Performance** (Node v26.12.0, Apple M2 with 8 GiB, machine busy with other jobs, so upper bounds): about 0.6-6 ms per frame for the hub and the games measured at 100x34 and 160x50 against a 33 ms tick, flat heap over 300 simulated seconds, and no leaked timers after 200 open/dispose cycles. Moonjars is the slowest (about 7-8 ms mean at 100x34, a few frames over 33 ms). No arcade performance thresholds exist in the repository.
- **Physical play:** the maintainer played the 33-game Arcade and confirmed the background-command behavior (Ctrl+T, the `/games` offer, the banner, the activity list, the exit slide, Color Orbit's retuned hop) in a real terminal. Results were not recorded per terminal (Ghostty or Zed separately), and not every game was played to its end; most games have otherwise been looked at as deterministic captures.
- **Background work:** 47 tests in `tests/backgroundActivity`, `arcadeCompanion` and `arcadeBackground`, plus four real-PTY tests (`tests/arcadeBackgroundLive.test.ts`: same session and shell, no shell frame reaches the host while the Arcade is open, the offer, the banner after 5 s; 0.08 CPU s per 3 s over a chatty command). An independent review's findings were fixed. A flicker the maintainer saw (the shell's own animation clocks painting between Arcade frames) was reproduced by a failing test and fixed at the cause.
- **Not performed:** Known limits (Pinball scale and bot cradling, Rover backflips, Kitten Parade difficulty, Moonjars hard decks, truncated top rows at 28 columns and more) are listed in [the status ledger](docs/development/arcade-expansion-status.md).

## [0.22.0] - 2026-10-21

**Native viewing and editing, Semantic Output, `/track` and input you can trust.** NMSh still runs your real zsh, Bash or Fish in one persistent session. This release reads files and completed output without leaving it (`/view`), makes a quick edit to a small text file (`/edit`) or opens it in your own editor, puts a test run's or a build's counts and failures in one row above its raw output (Semantic Output), and keeps one live, refreshed result of a command in the transcript (`/track`). Typing while a command runs now goes where it belongs on evidence only: a password is never shown, queued or run as a command because NMSh could not yet tell who reads it, and a slow prompt hook no longer eats the next command. Up and Down step through history one command at a time with the position shown, Ask can suggest a command from your local model (never run for you), and there are Bun, Nix shell and container modules, `/modules explain` and five more theme families.

v0.21.0 was prepared as a release candidate ([#429](https://github.com/raiseCatError/notMyShell/pull/429)) but never published; its work first ships here, so this section lists everything since v0.20.0.

**How this release was verified.** Automated: hosted CI (unit and real-PTY suites on macOS and Ubuntu, Node 22 and 26, a Fedora portability subset and the timing smokes) on the exact release commit, in a pull-request run and a dispatched run, both green. The maintainer accepted that hosted run in place of a local `npm run verify:release` on an 8 GB machine; the one local full run made (3,730 of 3,741 passing) had 11 load-sensitive live-terminal non-passes that passed when rerun alone, which is recorded here as that and not as a clean pass. **Physical: not performed for the nine required passes and the final-addition passes (multiline modes, images, text sizing, the document workspace, `/browser`, the arcade). The maintainer decided to release without them and accepted that risk; that is an acceptance, not a test result.** State, evidence and every open risk are in the [v0.22 physical QA record](docs/testing/v022-physical-qa.md) and the [v0.22 ledger](docs/development/v022-ledger.md).

### Added

- **Reviewed multiline pastes run three ways** ([design](docs/design/multiline-execution-modes.md)). *Review commands* now uses NMSh's shared panel components (a mode strip, the selection band, the standard controls) instead of bracketed options. **One at a time** (the default; each command waits in the composer for your Enter), **Queue all** (one confirmation, then the commands run in order; shell commands go through the session's queue and its failure policy, NMSh commands such as `/modules`, `/track` and `/view` run in NMSh and never reach the shell; it stops on a failure, a paused or cleared queue, or Esc, and never types into a running program) and **Run as block** (a shell-only paste as one original submission, with a warning that shells may read a block differently; not offered when NMSh commands are in the list, with the reason). A paste that cannot be separated safely offers Run as block, Edit and Cancel, with Edit as the default. Nothing runs until Enter on a mode.
- **Real images in NMSh** ([design](docs/design/graphics-service.md)). `/view image.png` (PNG, JPEG, GIF first frame, WebP through a converter already on the machine such as `sips`) opens the image in the viewer's own frame: fit with aspect kept, zoom 150–400% with pan, `n`/`p` through the folder's images, `c` copies the path. Markdown and HTML documents draw local images where they are written (inside the document's folder or git project); remote, `data:` and escaping references are never fetched and show `[image: alt]` with the reason; `i` opens a document's image. One graphics service decides how: Kitty graphics with Unicode placeholders where the terminal answers the protocol query, iTerm2 inline images (known host), Sixel where the terminal reports it, and quadrant-block character art everywhere else (Zed, Terminal.app, tmux, SSH, `NO_COLOR`). Settings → General → Images (Auto, Kitty graphics, iTerm2 inline, Sixel, Unicode, Off); `/doctor` shows what was detected and why. SVG is never drawn.
- **Larger headings where the terminal can scale text** ([design](docs/design/typography.md)). Kitty's text sizing protocol (OSC 66) is detected with the specification's cursor-position test, scale and width separately, and used for Markdown `#` and HTML `<h1>`–`<h6>` in `/view` (one 3×, 2×, 1.5× then ordinary-size scale), game titles and celebrations. Body text, code and tables are never enlarged; nothing is sized in a terminal that did not prove it, and sized text is never written to the transcript, a file or the clipboard. Settings → General → Text sizing (Auto, Off, Enhanced).
- **One workspace for Markdown and HTML files** ([design](docs/design/document-workspace.md)). `/view README.md` opens the file's source (read-only navigation); `h` shows the rendered preview, `e` edits the same buffer, `r` refreshes, `Ctrl+S` saves with the editor's atomic save, BOM and line endings kept. The preview shows the *current buffer*, saved or not, and never saves. While typing, `h`, `e` and `r` are text; `Ctrl+O` switches to the preview from anywhere. `/edit file.md` opens the editor directly. A file that cannot be edited safely stays readable in the viewer, with the reason.
- **`/browser`: a real browser in the terminal** ([design](docs/design/browser.md)). Chromium rendering (CSS layout, fonts, animations, JavaScript, SVG, canvas) of a page, shown through the graphics service as Kitty images where the terminal proved them and as character art elsewhere, with tabs, an address bar, back/forward, reload, find, zoom, mouse and keyboard forwarding, and a focus model that never steals typing. It uses a Chrome or Chromium you already have (set `NMSH_BROWSER` for another), starts only when a browser surface opens and stops when idle, in a throwaway profile; nothing is downloaded. Settings → General → Real browser (Auto, Off). With it, the workspace preview is the same Chromium (CSS animations and transitions included, scripts off unless you trust the file with `T`); without it, NMSh's own renderer stays the preview.
- **Vespyr Arcade** ([design](docs/design/arcade.md)). `/games` (also `/game` and `/arcade`; `/game run`, `flight`, `dash`, `sudoku`, `vespyr-doku`): **Vespyr Run**, **Vespyr Flight** and **Vespyr Dash** (endless, deterministic, with course generators proven fair by simulation), **Classic Sudoku** (four difficulties, notes, hints, undo, a unique-solution generator) and **Vespyr Doku** (a cat-placement puzzle on colored regions; one cat per row, column and region, none touching). Colors come from the active theme and Chroma; NO_COLOR, Safe Glyphs and reduced motion are respected; scores and unfinished puzzles stay in a small local file next to the configuration. The arcade never opens over a running command and closes if one starts, so a game can never take a password or a reply meant for a program.

- **`/view`, a native read-only viewer** for files and completed output ([#397](https://github.com/raiseCatError/notMyShell/issues/397)). `/view README.md` opens a file relative to the shell's directory (`~` for home): Markdown renders (`m` shows the source), source files get syntax colors and line numbers, `.diff`/`.patch` files and `git diff`/`git show` output read as diffs. `/view N` opens completed output N (numbered as `/copy` numbers it) and `/view` the latest; Actions → View output does the same for a block. Find with `/` and `n`/`N`, go to a line with `:`, `w` toggles wrapping (Left/Right scroll sideways), `l` line numbers, `c` copies the whole text, Esc closes. Viewing never changes the file or the transcript.
  - **HTML renders natively** ([#454](https://github.com/raiseCatError/notMyShell/issues/454), requested in physical QA): `.html`/`.htm` files, and HTML inside Markdown (a README's `<picture>`, `<img>`, `<div align="center">`, `<kbd>`), as terminal rows from a supported subset: headings, paragraphs, lists (nested, task boxes), tables, code, quotes, rules, emphasis, links and images. Nothing in it is run, styled by CSS or loaded: scripts, styles, embedded and interactive content are dropped, an image is its alt text (never fetched or read), links follow the same http(s)-only rule, and the parser is linear and bounded. `m` shows the source. Agent replies and other Markdown keep showing tags as text.
  - Limits: regular files only (directories, devices and pipes are refused), at most 8 MiB and 200,000 lines (the rest is named, with `less` or an editor as the way to read it), binary and UTF-16 files are refused, invalid UTF-8 is shown with `�` and a note. Control characters, escape sequences and invisible format characters are shown as visible marks, never interpreted. Open in pager, `less`, `bat` and Glow are unchanged.
- **`/edit`, a small native editor** for one text file ([#402](https://github.com/raiseCatError/notMyShell/issues/402)). `/edit notes.md` (or `e` in `/view`) opens the file in a panel: type, select with Shift, Ctrl+Z / Ctrl+Y undo and redo, Ctrl+F find, Ctrl+C / Ctrl+X copy and cut, Ctrl+S save, Esc close (it asks about unsaved changes). A path that does not exist yet is created on the first save. It is for quick edits, not an IDE: `vim`, `nano`, `micro` and your `$EDITOR` still run as usual.
  - Safe saving: the new text is written beside the file and renamed over it, keeping its mode, group, line endings, BOM and final newline; a symlink stays a symlink. If the file changed, was replaced or was deleted since you opened it, nothing is written until you choose Keep editing, Overwrite or Reload. A new file never replaces one that appeared meanwhile.
  - Limits: your own regular UTF-8 text files up to 1 MiB with one hard link, writable, with one kind of line ending. Others are refused with the reason and stay readable in `/view`. Extended attributes and ACLs are not carried over by a save. Unsaved text is lost if the NMSh window itself is closed.
- **Semantic Output** for test runs and builds ([#386](https://github.com/raiseCatError/notMyShell/issues/386), first phase). A completed block whose output NMSh recognizes gets one overview row with the counts the tool printed (`✔ node --test · 1,772 passed · 0 failed · 25 skipped`, `✘ TypeScript · 3 errors in 2 files`) and, when it listed failures or diagnostics, a details row that opens them, taken verbatim from the output. Recognized: Node's test runner (spec and TAP), Jest, Vitest, pytest, `cargo test`, `go test`, TypeScript, Rust and GCC/Clang diagnostics; anything else stays raw only, and short passing output gets nothing. Details start open when the raw output is folded; click the details row or use Actions → Show or hide details. The output itself, its folding, search, selection and plain `/copy` are unchanged. `/copy --semantic` copies the reading (raw for an output without one, as the note says) and `/copy --both` the raw output and the reading under labelled NMSh separators. Settings → Transcript → Semantic Output turns it off.
- **Native modules: Bun, Nix shell and container** ([#364](https://github.com/raiseCatError/notMyShell/issues/364)). Bun's requested version comes from `.bun-version` or `package.json` (`packageManager`, `engines.bun`) and the active one from its install location; the Nix shell module shows `pure`/`impure` from `IN_NIX_SHELL`; the container module names Docker, Podman, a dev container or Codespaces from marker files and host variables. None runs anything; all are off until enabled in `/modules`, which recommends Bun and Nix when their files are present.
- **`/modules explain` and `/modules timings`** ([#365](https://github.com/raiseCatError/notMyShell/issues/365)) write a plain-text report into the transcript: each configured module's surface, whether it is on screen and why (including when the Context Rail or Status Strip left it out, or shortened it, to fit the width in the last frame), and its sources' state, age and last collection time; or the slowest last collections. They read what the Context Engine already has and collect nothing.
- **Five more bundled theme families** ([#401](https://github.com/raiseCatError/notMyShell/issues/401)): Ayu (Dark, Mirage, Light), Kanagawa (Wave, Dragon, Lotus), Everforest (Dark, Light), Flexoki (Dark, Light) and Night Owl (Night Owl, Light Owl), with colors copied exactly from each project's MIT-licensed source at a recorded revision. They theme NMSh's own prompt fills and chrome only; the terminal's own colors and configuration are never changed. Existing theme ids and saved choices are unchanged, and Lavender stays the default. Theme Studio's Built-in list gains `/` to filter by name, family, or `dark`/`light`.
- **`/track`** keeps one live result of a finite command in the transcript, refreshed in place ([#393](https://github.com/raiseCatError/notMyShell/issues/393)). `/track df -h` or `/track --every 5s -- docker system df` writes the command once, then shows a status row (`live · every 5s · updated 13:49:25 · exit 0`, a failing exit, a timeout, paused, stale, refreshing) and the latest result under it, with a stable height. The shell stays free; nothing accumulates per refresh, and find, selection and `/copy` never include the live rows. `/track copy` copies the latest result, `/track refresh`, `pause`, `resume` and `stop` control it, and stopping leaves the last result in the transcript once. Samples run `sh -c` from the starting directory with your shell's PATH (not its aliases or functions), never overlap, and are bounded (200 kB, a timeout, at most 8 trackers); destructive and unknown commands are refused or need a Yes, as for `/watch`. Trackers stop with the window that started them. `/watch` keeps its manager and its behavior; both share one scheduler, which gains stricter interval parsing, refusals for substitutions, background jobs and heredocs, UTF-8-safe bounded capture, visible timeouts and a stop grace period (from draft #394).
- **From `/view` to your own editor** ([#366](https://github.com/raiseCatError/notMyShell/issues/366)). In `/view` of a file, `o` opens it at the first line on screen through the same bridge as `/open`: Zed or VS Code (around NMSh, or chosen in Open with) opens beside NMSh, and a terminal editor from `$VISUAL`/`$EDITOR` gets its command placed in the composer for you to run, never run for you. A draft already in the composer is never replaced, and with no editor known the viewer says how to set one. A file `/view` shows only in part, or cannot decode, now names this way to the rest.
- **Choose a terminal editor for `/open` when VISUAL and EDITOR are not set** ([#366](https://github.com/raiseCatError/notMyShell/issues/366)). Settings → Terminal editor (also in `/providers`) lists Neovim, Helix, Micro, Vim, nano, Emacs and Kakoune, marks which are installed here, and saves one you have; one that is not installed cannot be chosen, and NMSh never installs an editor. `/open` then puts that editor's command in the composer for you to run, with the line and column in the form that editor documents (`hx file:12:5`, `nano +12,5 file`, `emacs -nw +12:5 file`, `nvim +12 file`). Zed or VS Code (around NMSh or chosen in Open with) and VISUAL/EDITOR still come first. When nothing is set, the message names the editors installed here.
- **Command suggestions in Ask, from your local model** ([#432](https://github.com/raiseCatError/notMyShell/issues/432), first part). Off by default; Settings → Ask → Command suggestions → Local model turns them on. For a shell task Ask does not do itself (`/btw convert every png here to webp`: changing files in bulk, or finding them by size, age or duplicates), or a request it cannot place, your local model (set up in `/llm`) may suggest one shell command; with suggestions off, Ask says it does not run such tasks and where suggestions are turned on. Ask shows it with NMSh's own check (reads only, changes things, installs software, destructive), never the model's, and offers Copy or Insert only: Insert puts it in the composer unsent, and only your Enter runs it. The model is sent the request, the shell and the OS family, nothing else; requests Ask refuses stay refused. Remote providers are not part of this release.

### Changed

- **Reviewing a multiline paste starts on One at a time, and `q`, `b` and `o` only choose a mode.** The first Enter on the review no longer queues the commands (v0.22 candidates did); choose Queue all (`q`) and press Enter. The old bracketed options are gone.
- **`/view` on an editable Markdown or HTML file opens its source first** (`h` for the rendered view, `m` is no longer needed). Files the editor refuses (too large, read-only, mixed line endings) still open rendered in the read-only viewer.

- **A line entered with Enter while a command runs waits for your approval; Ctrl+Q queues a command to run after it** ([#426](https://github.com/raiseCatError/notMyShell/issues/426)). While a command runs and NMSh sees no question, Enter used to queue the line to run by itself after the command. That line can be the command's reply to a read NMSh never saw, and nothing about its text tells the two apart (`yes`, `ls`, a one-time code and `X=1` are all valid replies), so it is now held: the queue shows it as `(typed while make ran)`, never by its text, and it runs only once you approve it at the prompt (Enter reviews it, Tab shows it, Enter approves; `e` edits; `n` pauses the queue). **Ctrl+Q** is the explicit way to queue a command to run after, as before. The composer says so while a command runs: `Enter holds it for approval · Ctrl+Q runs it after · Ctrl+S sends to make`. A line typed right after Ctrl+C or Ctrl+Z is for the prompt the stop brings back: it runs there once the prompt is back. If the program survived the stop, the line goes to it instead (at once if it asks, else when the moment of the stop has passed, about 2 s); what it never reads waits for approval. A line begun while a slow prompt hook holds the prompt back, after the shell said the command is done, runs at the prompt.
- **Up and Down step through history one command at a time, however many lines a command has** ([#389](https://github.com/raiseCatError/notMyShell/issues/389)). Once Up has recalled a command, each Up or Down moves to the next older or newer command, even when the recalled one spans several lines or wraps; before, a recalled five-line command took five extra presses to pass. Typing, pasting, deleting, moving the caret or selecting in a recalled command makes it a draft again, where Up and Down move between its lines as before, and Down past the newest command restores exactly what you had typed. Editing a fresh multi-line draft is unchanged.
  - While you step through history, the bottom composer rule shows where you are: `History 2/120`, counted back from the newest command. It sits on a rule that is already there (the top one when the bottom one is not free), in the same subtle color as other text on those rules, and never covers Keep Awake or the prompt. It never adds a row or moves anything; with no free rule, or no room on it, it is not shown.

### Fixed

- Multi-line progress displays that redraw their own rows (cursor up and erase line, as concurrent downloads and container pulls do) now update in place instead of leaving a copy of every frame in the transcript ([#388](https://github.com/raiseCatError/notMyShell/issues/388)). A program can redraw only its own recent rows, at most a screen height up, never NMSh's lines or earlier commands; `/copy` copies the final rows once. Rows are the terminal's rows: a line wider than the window counts as the rows it occupies, so a display that redraws over its own wrapped line no longer erases the log lines above it at narrow widths. A status row an installer reserves below a scroll region is not written into the log. Absolute cursor positioning is not mapped.
- Pasting several lines that mix NMSh commands with shell commands no longer sends NMSh's lines to the shell or turns the block into one unknown NMSh command ([#450](https://github.com/raiseCatError/notMyShell/issues/450), found in physical QA: `cd modules/bun-app` then `/modules` gave `zsh: no such file or directory: /modules`; four `/track` lines gave an unknown-command error). Enter on such a block, pasted or typed with Ctrl+J, runs and queues nothing: it opens the reviewed list, and **One at a time** puts each command in the composer, unsent, in order. Each runs on your own Enter, the next is offered only after the one before succeeded, and Esc stops. Multi-line shell text (scripts, heredocs, quotes) is unchanged.
- While a program waits for input, its headline keeps the queue in view and says when queued commands now wait for your approval (`≡ 2 queued · 2 for approval`); on a narrow screen it shortens the headline before dropping the queue to a bare count ([#452](https://github.com/raiseCatError/notMyShell/issues/452), physical QA).
- Ask with your local model no longer answers a shell task with an unrelated screen: `/btw convert every png here to webp` showed the folder listing, because the intent model read it as "list files" and that answer stood ([#446](https://github.com/raiseCatError/notMyShell/issues/446), physical QA). A refusal is never re-read by the intent model either, in Auto or Always. A model that suggests no command now says so.
- Markdown wrapping no longer glues two words together when the second fits only without the space before it (`A calmerterminal`), in every Markdown surface.
- A queued command whose command word was still being classified when the next prompt reported new shell knowledge no longer keeps the unclassified color ([#408](https://github.com/raiseCatError/notMyShell/issues/408)).
- With a slow zsh configuration (one that takes longer than a second and a half to load, as nvm or a large framework can), command colors no longer stop for the rest of the session: the first lookup waited on the configuration, timed out, and ended the helper that tells known commands from unknown ones.
- Paste review and `/track`: a redirect into a file is recognized wherever `>/dev/null` also appears (`echo x > ~/.zshrc 2>/dev/null` was labelled read-only), and `>|` is a redirection, not a pipe.
- `/track` and `/watch` no longer start, without asking, commands that change things through the network or another command: `env <command>`, `NAME=value` prefixes, git's `-c`/`--ext-diff`, `npm publish`/`login`/`x`, `pnpm dlx`, `ssh`, `curl -X POST`/`-d`/`-o file`, plain `wget`; options that write files (`git … --output`, `sort -o`, `jest -u`, `--fix`) are refused. Read-only probes (`ping`, `dig`, `nc -z`, a curl GET) still start at once, and `npm test 2>&1` is no longer refused as a background job ([#393](https://github.com/raiseCatError/notMyShell/issues/393)).
- `/track stop` and a closing window end every process a tracked command left in its process group, including one that ignored TERM; a tracker whose directory disappeared names it instead of reporting `spawn /bin/sh ENOENT`.
- **Fish 3: NMSh no longer interrupts Fish's own output** ([#443](https://github.com/raiseCatError/notMyShell/issues/443)). The shell's terminal size followed NMSh's own layout, so a command starting or ending, a growing composer, a completion menu, a notice or Settings each resized it and signalled the running program (SIGWINCH); Fish 3 does not retry a terminal write that signal interrupts, and lost part of its output (`write: Interrupted system call`). The terminal's size now comes from the window and the configured layout only, and while a command runs only a real change of the window resizes it. Full-screen programs still get the whole window; the transcript can be a few rows shorter than the terminal, as it already was under Dock Top, and shows the newest rows.
- A command typed while the shell was showing its prompt again (after Ctrl+C, or after any command when a prompt hook is slow, as a heavy theme or `nvm` can be) no longer loses its beginning ([#436](https://github.com/raiseCatError/notMyShell/issues/436)). NMSh no longer reads the shell's own prompt hooks as the finished command waiting for input (`Probably waiting for input` while the prompt came back), and a late report of the question Ctrl+C ended no longer turns what you typed after it into a discarded reply; the rest of the line used to run on its own (`cho Y …`, command not found).

### Security

- **Images and documents cannot read or reveal what they should not.** Image references from a document are checked lexically and then on the real path against the document's folder or project before any file is opened, so a symlink or `../` out is refused and nothing is learned about paths outside; remote and `data:` references are never fetched; files are read from a checked descriptor with size, pixel and inflation limits; SVG is never rendered; file names are drawn with control characters replaced.
- **The browser preview is isolated.** A document preview is served from memory on a loopback-only server behind an unguessable path, with a Host check, a strict path and file-type allow-list and a restrictive Content-Security-Policy; scripts are off unless you trust the file, and a preview can reach only its own origin (a clicked link is reported, never followed). The browser runs with sandboxing on, no remote debugging port (a pipe), no extensions, downloads and permission prompts denied, a minimal environment and a throwaway profile; previews share no cookies with browsing.
- **A game can never own the keyboard of a running command.** The arcade and the browser refuse to open while a command runs, and close at once if a command starts.
- **Passwords and other replies are never shown, queued or run as a command on a guess.** Typing while a command runs can no longer be shown, queued or run as a command before NMSh knows whether that command reads it ([#426](https://github.com/raiseCatError/notMyShell/issues/426)). On a heavily loaded machine a reply typed right after starting a prompt-less read (`read -r reply`, `read -s`) used to be queued, and a password could be queued as a shell command or shown in the composer. Keys now wait for NMSh's check (`Checking whether … · your typing is kept` after 0.8 s). When the check cannot tell, the typing stays held and hidden — `Can't tell whether <program> is reading your typing` — until you choose: Ctrl+S sends it to the program, Tab shows it in the composer, Esc discards it. Input with echo turned off is never drawn, whatever else NMSh knows. Ctrl+C discards held typing, as a terminal flushes its input. When a command ends while typing is held for its check, including before its prompt returns while the shell's prompt hooks run, typing that may have been a reply or a password is discarded with a note, never run; plain type-ahead that the check cleared at once stays for the next command. After NMSh answers a hidden question, typing that a check still finds next to hidden input may be the reply to a second question with no prompt: if the command ends first, it waits at the prompt, hidden (`held, not run · Tab shows it · Esc discards it`), and only your Tab and Enter run it. A reply typed and entered before a question with no prompt existed is queued like any command (NMSh could not know); once the command asks for input that NMSh sees, hidden or not, the commands queued while it ran wait for your approval instead of running after it. Tab shows held typing as text only: a Ctrl+Q or any other key typed while it was held never queues, sends or runs it. A password typed in the composer before the program printed its prompt (as with `sudo`) leaves the composer when the program asks for hidden input, is never sent as the answer, and is held at the prompt when the command ends; an Enter typed with it is dropped rather than sent as an empty answer. Type-ahead on an idle machine is unchanged.
- **No reply becomes a shell command by itself** ([#426](https://github.com/raiseCatError/notMyShell/issues/426)). A line entered while a command runs, before a question NMSh saw, is held for your approval (see Changed), whatever it looks like: a reply that is itself a command name (`yes`, `sudo`, `ls`), a one-time code or an assignment used to run after the command succeeded when its read gave up unseen. The session's owner enforces the hold, not only the window: such an entry cannot be set to run by itself, and is shown as where it came from until you show it. It is never offered again by Up and never reaches the shell's history or NMSh's journal unless you approve it. Keys held while NMSh checked who reads them, whose command then ended, are held the same way instead of running at the prompt.
- **Typing a command never read cannot reach the shell** ([#426](https://github.com/raiseCatError/notMyShell/issues/426)). Input NMSh delivers to a program (an answer, keys for its own interface) that the program never reads stays in the terminal when its command ends; the shell then read a whole line as its next command and glued a partial one (a password typed into a read that timed out) onto the command NMSh submitted next. Now, when NMSh delivered input to a command, the shell's first prompt hook takes whatever is left out of the terminal (with `stty`, `head` and `od`, before it reads its next command line) and hands it to NMSh, which holds each line for your approval; input that arrives once the shell says the command is done is held and never written. zsh, Bash and Fish.
- **An older session service fails closed** ([#426](https://github.com/raiseCatError/notMyShell/issues/426)). A window attached to a service from an older NMSh (v0.20.0's), which cannot say what its checks saw, holds typing while a command runs, hidden, until you choose (Ctrl+S, Tab or Esc), and a line entered then waits for approval; the window says so, says what remains, and that the service restarts once its sessions end.

### Known limitations
- `/track` is window-owned: trackers stop with the window that started them, and a resumed session shows the last result, not a live one. Samples run `sh -c` with the shell's PATH, not its aliases or functions.
- Semantic Output is a first phase: built-in recognizers only (no `jc`, `delta` or other external providers), the raw output is not fully collapsed behind the reading, and find searches the raw output only.
- `/edit` does not carry over extended attributes or ACLs, and unsaved text is lost if the window itself closes; the size and file-kind limits are listed under Added.
- Progress redraws: absolute cursor rows (`CSI H`/`f`/`d`) are not mapped and scroll regions are not emulated ([#388](https://github.com/raiseCatError/notMyShell/issues/388)).
- `/modules explain` covers the Context Rail and Status Strip; the Main Prompt has no per-segment truncation trace ([#365](https://github.com/raiseCatError/notMyShell/issues/365)).
- Oxocarbon, GitHub Primer, Material/Palenight and Monokai are deferred, with reasons in `docs/design/theme-families.md` ([#401](https://github.com/raiseCatError/notMyShell/issues/401)).
- **Input while a command runs** ([#426](https://github.com/raiseCatError/notMyShell/issues/426), [#436](https://github.com/raiseCatError/notMyShell/issues/436)). What NMSh can and cannot tell:
  - *Nothing typed while a command runs becomes a shell command by itself:* a line entered then waits for approval, typing the command never read is taken back from the terminal when it ends and waits for approval, and a line after Ctrl+C runs only at the prompt the stop brings back. What runs by itself is what you submit at the prompt, queue with Ctrl+Q, or approve.
  - *A reply to a read NMSh has not seen yet* (no prompt, echo on, on a loaded machine, or any program's read on macOS) is held for approval instead of reaching the program: the program keeps waiting until you answer it again or send the line with Ctrl+S. A line typed after Ctrl+C for a question the program asks without NMSh seeing it, which then gives up before the program ends, still runs at the prompt.
  - *Keys typed into a full-screen or interactive program as it exits* (`:q` then `ls` at once) are the program's: those it never reads are taken back when its command ends and wait for approval, instead of running at the prompt as in a plain terminal.
  - *An answer NMSh sends to a question it sees* reaches the terminal at once. If the program stops reading in the same instant (a timed read giving up exactly then), NMSh cannot take back what the kernel already holds, but the shell's prompt hook takes it out before reading its next command, and NMSh holds it. Input sent within the instant between the shell finishing the command and NMSh learning so (well under a millisecond on an idle machine) can still reach the shell; that window is the limit of what a terminal frontend can see.
  - *Hidden input* (echo off) is never shown, queued or run on a guess. Typing NMSh cannot place is held until NMSh sees the program's question (then it goes to the program, as its answer) or you choose (while the command runs: Ctrl+S sends it, Tab shows it, Esc discards it; at the prompt: Tab or Esc); a command that ends while typing was held past 0.8 s discards it.
  - *History:* typed input reaches your shell's history and NMSh's journal only when it runs as a command (a composer line you submit, a Ctrl+Q entry or one you approve); the transcript also shows what a program echoes back (a visible reply), never hidden input. Held typing and entries waiting for approval stay in memory and are never written to disk.
  - *Typing that reaches a finished command's prompt hook in pieces* (fixed in this release): a line typed after the shell said the command was done, and before its prompt, was held as one approval entry per piece the terminal delivered it in, so a slow macOS prompt hook turned `echo NEXT` into about sixteen entries of fragments (`e`, `c`, `h`...). Nothing ever ran by itself, but approving them ran the fragments. The pieces are put back together as the lines typed (corrections such as Backspace reach the text they correct), and a line left without Enter is held once the typing stops.
  - *A line entered the instant a queued command is approved:* a window learns what the shell is doing from the shell's events, which reach it a few milliseconds after the shell acts (longer on a loaded machine). A line submitted in that gap, before the window has seen the approved queue entry start, runs after it, once and in order, with nothing lost or run unapproved, but the window attributes the first prompt to the line it submitted: the queued command's transcript record is missing and the submitted line is recorded twice. Found by a live test that typed within about ten milliseconds of the approval; the test now waits for the approved command's record.
  - *Prompt hooks:* zsh's single `precmd` function and Fish's other `fish_postexec` handlers run before NMSh's done marker, so a slow hook there can still be read as the command waiting (`Probably waiting for input`). What you type then is held for approval or taken back at the hook, never run by itself.
  - *An older session service* (v0.20) has none of the shell-side protections: typing a program receives but never reads can still reach the shell there. This window fails closed (see Security) until the service restarts.
- Keys typed *during* a Fish `read` stay subject to Fish's own editor queries ([#356](https://github.com/raiseCatError/notMyShell/issues/356)). Keys typed after its answer, before the prompt is back, are no longer read by Fish as the next command: they are taken back when the command ends and wait for approval, never lost.
- Ask's command suggestions use your local model only; remote providers are not part of this release ([#432](https://github.com/raiseCatError/notMyShell/issues/432)). A suggestion is only as good as the model: the small recommended model (Qwen3 0.6B) often suggests an imprecise command or none; NMSh labels each one with its own check and never runs it.
- NMSh's own HTML renderer (the fallback preview when no browser is installed or the setting is Off) shows a subset: no CSS layout, forms or embedded media. With a browser installed the preview is Chromium's.
- **Hosted macOS live-terminal tests are intermittent.** Over the last two days about 4 in 10 of the repository's hosted CI runs passed on the first attempt, before and after this integration; the failures were live-PTY tests on macOS (typing-after-read, input ownership, queue ownership) and, before they were fixed, two multiplexer tests. Two causes were found and fixed (test timing assumptions; typing held in pieces after a command was done), but the cause of the remaining macOS failures is not established, and they are not shown to be harmless. A failed hosted job on a pull request that passes on the dispatched run is that known instability and not by itself a regression; a failure that repeats on a rerun is not.
- **Not physically verified (NOT RUN):** Kitty graphics and Unicode placeholders in Ghostty and Kitty, OSC 66 text sizing in any terminal, character art in Zed and Terminal.app, iTerm2 and Sixel output, Chromium frames in any terminal, and play of the five games. Automated tests cover the protocol output, fallbacks and game rules, not how any of it looks or feels in a real terminal. See [v0.22 physical QA](docs/testing/v022-physical-qa.md).
- Ghostty accepts text sizing sequences but is not known to draw scaled glyphs, so Auto leaves it off there; Enhanced is the explicit override.
- Images are never fetched from the network, animated images show their first frame, and WebP needs a converter that is already installed (`sips` on macOS, `dwebp`, ImageMagick or `ffmpeg`).
- Inside tmux, screen and Zellij images are character art and text is not scaled (graphics would need passthrough, which NMSh does not use).
- The browser preview refreshes when you ask (`r`); there is no split view, so no automatic refresh while typing. Leaving the preview closes its page; the scroll position is kept across refreshes only. `/browser` forwards what a terminal can express: no smooth scrolling, gestures or file pickers, and downloads are refused.
- Linux stays beta: automated CI on Ubuntu and Fedora, no physical pass. Everything listed under v0.20.0's known limitations still applies.
- **Linux (beta) with Fish 3** ([#443](https://github.com/raiseCatError/notMyShell/issues/443); shown with Fish 3.7.0 on Ubuntu 24.04). Fish 3 does not retry a terminal write that a window-size change interrupts. NMSh no longer causes one (see Fixed), and its own markers on Fish 3 go through `cat`, which does not lose them ([#449](https://github.com/raiseCatError/notMyShell/pull/449)). A real resize of the window while Fish itself writes output (`echo`, `printf`, `string`) can still lose part of that output, with `write: Interrupted system call` in its place: that is Fish 3's own handling of the signal, which NMSh cannot change and which happens in any terminal. Fish 4, zsh and Bash retry. The new CI stress loop did not reproduce the loss on either build, so the improvement is shown by the removed cause (no signal from NMSh's own layout), not by a measured loss rate.

### Added

#### Input awareness ([#348](https://github.com/raiseCatError/notMyShell/pull/348))
- **Input awareness:** a command that waits for an answer is no longer just "Running". NMSh reads the terminal's own state, without touching the program. A password or other no-echo read, or a single-key question such as `e2fsck`'s `Fix<y>?`, is confirmed; on Linux, any blocking read of the terminal is confirmed too. An ordinary line question left open by an idle process is shown as "Probably waiting for input". The question stays visible beside the composer however far the transcript has scrolled, and the window title, `/sessions`, `/resume` and a cross-session notice show the wait. Hidden and single-key input goes straight to the program, keystroke by keystroke, and is never shown or kept. A reply left unsent when the command ends is discarded, never run as a shell command. Waiting time is measured separately from wall-clock time and reported on completion. See `docs/design/input-awareness.md`.
- Fish's own `read` and other builtin readers are recognized from authenticated terminal ownership, and input typed during startup, before the shell is ready, or while a hidden read is open goes only to the program that currently owns the terminal.

#### Command queue ([#357](https://github.com/raiseCatError/notMyShell/pull/357))
- Commands typed while another runs are **queued in the same shell** and run after it, one at a time, only when the shell reports it is ready, keeping the directory, variables and functions. Multiline entries keep their meaning (Fish `begin`/`end`, zsh and Bash brace groups). `/queue` shows, edits, reorders, pauses, resumes or clears them; queued command text is drawn, never interpreted.
- When the running program is waiting for an answer, Enter answers it and **Ctrl+Q** composes a queue entry instead. While a program reads keys directly, Ctrl+Q takes the next command for the queue and **Ctrl+S** sends the composer's text to the program.
- A failure or interrupt **pauses** the rest of the queue. Detach and reattach never submit an entry twice; switching shells pauses the queue, and a shell that exits drops its entries instead of replaying them in another shell. Silence is never taken as completion.

#### Copy and Smart Folding ([#358](https://github.com/raiseCatError/notMyShell/pull/358), [#350](https://github.com/raiseCatError/notMyShell/issues/350))
- `/copy N`, `/copy -N` (the latest N), ranges `A-B` and lists `1,3,5`; `--status` adds the completion row; `/cp` is the same command in every form.
- `/copy ui` opens an interactive picker; `/copy settings` chooses Quick Copy or the picker by default and whether copies include status.
- A sticky Copy control keeps block actions reachable while a long block's header is scrolled away.
- **Smart Folding** keeps long diagnostics readable; the full output stays stored, and copies include folded lines.

#### Copy as Report ([#360](https://github.com/raiseCatError/notMyShell/pull/360), [#351](https://github.com/raiseCatError/notMyShell/issues/351))
- One or several command blocks as a Markdown or plain-text report with command, output, directory and exit status, always shown for review first. Enter copies exactly the reviewed text; cancel leaves the clipboard unchanged.
- Likely secrets and private paths are **redacted** in the review before any Markdown is added; edited text is rescanned, changed lines are marked, and an unredacted choice is labelled. Redaction is best-effort (see Known limitations).

#### Compare output ([#361](https://github.com/raiseCatError/notMyShell/pull/361), [#352](https://github.com/raiseCatError/notMyShell/issues/352))
- `/compare` (the latest output with its previous run), `/compare N`, `/compare N M` (numbers as for `/copy`), or Actions → Compare output…: a line diff with counts, hunks and collapsed unchanged regions, side by side from 140 columns and unified below, with labelled whitespace normalization. Output lost while detached is marked incomplete.
- In the comparison, `r` opens the diff as a reviewed, redacted report. `c` copies the sanitized plain diff **directly, without redaction** (it shows a caution when the detector flags a likely secret).

#### References, paste review, clips, pins and recipes ([#368](https://github.com/raiseCatError/notMyShell/pull/368), [#353](https://github.com/raiseCatError/notMyShell/issues/353)–[#355](https://github.com/raiseCatError/notMyShell/issues/355))
- Files, links, commits and device names in a block's output can be opened, copied or staged from its Actions; nothing runs by itself.
- **F8 / Shift+F8** walk failed commands (by exit status, not text matching) and keep your draft; the palette offers Previous/Next failed command too.
- **Paste review:** a pasted zsh, Bash or Fish sequence can be split into commands and parse-checked without running anything; confirming queues the reviewed list. `/ps` reads the clipboard only when you run it.
- **Queue conditions:** an entry can wait for its own approval (withdrawn if the entry is edited) or be marked `always` to run even after a plain failure, never after an interrupt.
- `/clips`: text deliberately kept in memory for this window, reviewed before insertion and gone when the window closes. Optional clipboard-change hints on macOS (`/clips suggestions on`, off by default) read only the pasteboard's change counter, never its contents.
- `/pins`: pinned commands with their directory (palette → Pin selected history command) and recipes with quoted placeholders, staged or reviewed and queued, never run automatically.

Failures, interrupts, agents and queued runs keep factual wording, and copies, reports and restored records always store the factual form.

- `/theme` imports **Starship** configurations as Native themes from their static colors only; format strings and custom commands are never evaluated, and the preview lists what was not carried over.

- `/sessions` refreshes live session facts without losing the selection, query, draft or focus.
- A clipboard write is reported as complete only when the whole payload was delivered and the clipboard tool exited successfully.

### Security
- Every session socket request (listings, notices, dismiss, rename, kill), not only create and attach, verifies the private runtime directory's ownership before connecting.
- A client cancelled before it started discards output withheld for it instead of exposing it.

- Activity wording becomes **Expressive** by default, including for existing settings. Choose Classic in Settings → Live activity → Activity wording to keep the previous wording.

### Known limitations
- Physical-terminal status for these features is recorded under v0.20.0's known limitations.
- Redaction is pattern-based and can miss custom, encoded or unknown secret forms and private paths; review every report. Comparison `c` and plain `/copy` copy without redaction by design.
- A clipboard tool that fails after it started writing may already have changed the clipboard; NMSh cannot roll it back.
- Fish can drop type-ahead entered while its own `read` is still running, as in any terminal ([#356](https://github.com/raiseCatError/notMyShell/issues/356)).

- A forced SIGKILL of the frontend can bypass helper cleanup; normal stop, SIGTERM and SIGHUP clean up owned helpers.
- Exact last-frame module width-compaction explanations and dedicated external source previews are not included ([#365](https://github.com/raiseCatError/notMyShell/issues/365)).
- Ruby and PHP were the candidate's only new runtimes; the full native runtime set (.NET, Swift, Zig, Deno, Elixir, Dart, Flutter, build systems) is part of v0.20.0.

### Fixed
- **Absolute executable paths** typed in the composer (`/Volumes/tools/adb devices`, `/bin/zsh`, `/usr/bin/env …`) run in the shell exactly as typed instead of being refused as unknown NMSh commands, and keep shell completion and suggestions. A first word with a `/` after the leading one is a path (no NMSh command name contains one), so `/zsh` still switches shells while `/bin/zsh` runs; a directory used as a command gets the shell's own behavior.
- **`/copy`** and `/copy N` copy only the command's own output (stdout and stderr, line breaks and spacing kept), never NMSh's completion row such as `✔ Completed · 21.6s · 15:42`, nor NMSh lines (such as a `/copy` confirmation) added inside a running command's block; output that merely looks like a completion row is kept. A command that printed nothing leaves the clipboard as it was and says so.
- **Folding after a screen clear:** after `clear`, tmux, or any program writing `ESC[2J`/`ESC[3J`, fold rows such as `15 lines shown · Ctrl+O` no longer appear inside the next command's output, and Ctrl+O no longer folds another command's lines together with `/copy` and status rows. A clear now retires the records of the lines it removed; a command that clears the screen owns, and `/copy` copies, what it writes afterwards. Transcripts saved before this fix are repaired when opened: a record is kept only if its lines show it owns them, and older commands from before an unrecorded clear lose their fold control and `/copy N` while their lines stay visible. Full-screen programs, partial erases (`ESC[J`, `ESC[1J`, `ESC[K`) and progress redraws never clear the transcript.
- **Fish keystrokes around `read`:** keys typed quickly around a fish `read` are no longer lost to NMSh's query round trip; NMSh answers fish's terminal queries itself, as it already did at fish's prompt, and input waits until fish has redrawn its prompt. For any program, keys never overtake the answer to a device-attributes query.
- **Passthrough programs get their bytes exactly as written:** output processing (`ONLCR`) is off while a program owns the terminal, so raw-mode TUIs that move down with a bare LF no longer overwrite their own prompt or jump the cursor. Two-byte Alt+key prefixes are no longer held as possible terminal answers.
- Terminal queries a program writes before it takes the screen (synchronized output, grapheme clustering, colors) reach the host, and the answers go back to the program instead of the key decoder.
- Ownership handoff: output from the first sign a program owns the screen (alternate screen, an input mode, a kitty keyboard push) belongs to the program, so its paint no longer stays in the transcript after it exits; undrawn sequences no longer print debris (`ESC ( B` → `B`, `ESC[NaN;2m`), zero color components are kept, and half-decoded input is dropped at every handoff.
- **tmux:** `tmux` typed in the composer opens ordinary panes again (tmux no longer inherits NMSh's private `ZDOTDIR` or `POWERLEVEL9K_DISABLE_PROMPT`, and children get the person's own `XDG_CACHE_HOME` back), and a window says when its session service is an older build that still writes the old bootstrap. The mouse wheel scrolls the NMSh transcript instead of cycling composer history (NMSh now asks tmux for button and SGR mouse reports, which tmux forwards with its `mouse` option on or off). NMSh no longer wraps frames in its own DEC 2026 synchronized-output block inside tmux, and repaints that leave the caret in place no longer toggle cursor visibility, so host cursor trails and blink stop jumping.
- **Terminal title** (from the Ghostty QA pass, [#321](https://github.com/raiseCatError/notMyShell/issues/321)): Project and session titles show the session's name at once after `/rename` (and its signature after a reset); after Vim or another passthrough program sets its own title on exit, NMSh writes its title back as soon as it has the screen.
- Theme Bridge colors are valid on 16- and 8-color terminals (theme ANSI slots instead of 256-color codes for less/man, listings and Vim).
- Apply themes → Follow NMSh / Choose theme themes NMSh's own fzf launches even when fzf's Manual setting is Independent.
- A detached session's spooled prompt events are no longer dropped on replay when the shell's knowledge exceeds 64 KiB.
- Unmodified F1 in its kitty keyboard form (`CSI P`) opens the palette.
- Ask's config edits no longer refuse files in a home folder or project reached through a symlink (macOS `/tmp` and `/var` are symlinks); a symlink leading out of them is still refused.

### Security
- Context discovery never runs a discovered executable; one inside the current workspace (followed through symlinks) is not even inspected. Hostile-workspace coverage spans control/bidi/OSC payloads, huge, malformed and symlinked files, fake executables, malicious PATH entries, `.envrc`, kubeconfig `exec`, hostile Git metadata and malicious packs.
- Every NMSh display path (prompt, modules, path, Status Strip, `/prompt` and `/modules` disclosures, fact cache, historical prompt blocks, welcome, startup picker, `/resume` and live-session lists, `nmsh packs` and `nmsh agent-status` output) removes escape sequences whole instead of leaving visible debris; an unterminated OSC in a session-reported directory can no longer swallow the startup screen. Hostile directory names in the terminal title lose whole escape sequences instead of showing `]0;PWNED` debris.
- Retained control sequences are bounded: the transcript parser keeps at most 8 KiB of one unfinished sequence (OSC, DCS, SOS, PM and APC are discarded to their terminator), NMSh's shell markers are capped at 1 MiB and the key decoder at 256 bytes.
- Keys held behind a terminal answer are discarded by Ctrl+C before it is delivered, as a terminal discards pending input, so a cancelled line cannot still run; bracketed pastes are never searched, split or reordered by the hold.
- `/github` writes nothing to GitHub and stores no credentials; IPv4 and IPv6 addresses in GitHub error text are shown as `[address]`.

## [0.6.0] - 2026-09-29

Sessions & Continuity: persistent live sessions you can detach from and reattach to, a Flow composer, and a `/layout` showcase.

### Added
- **Persistent live sessions:** zsh now runs in a small per-user session service (`nmshd`, started on demand over a private Unix socket), so closing a window **detaches** its shell instead of ending it. Running commands keep going. `exit`, Ctrl+D and `/zsh` still end the session. `NMSH_SESSION_SERVICE=0` runs the shell in-process as before.
- **Reattach:** get back to a detached session from the startup prompt, from `/resume` (LIVE sessions are listed above ARCHIVED transcripts; Enter attaches, and Ctrl+K kills after confirmation), or with `nmsh --attach <id>`. `nmsh --sessions` lists live sessions, and `nmsh --new` always starts a fresh one. A session attached in another window is never taken over.
- **Output while detached:** what a detached session prints is kept (1 MB in memory, then up to 64 MB spooled to disk; `NMSH_BACKLOG_MEMORY_BYTES`, `NMSH_BACKLOG_SPOOL_BYTES`). It is added to the transcript on reattach, with a note of commands that completed and anything that exceeded the limit. Fullscreen apps are repainted at the new window size.
- **Multiplexer interoperability notes:** [docs/architecture/multiplexer-interop.md](docs/architecture/multiplexer-interop.md) records how NMSh behaves inside and around tmux and GNU screen (rendering, resize, job control, fullscreen, paste, and live-session detach when a pane closes), what remains unverified (Zellij), and follow-ups. NMSh stays independent of any multiplexer.
- **Live session status:** `/resume` LIVE rows and `nmsh --sessions` show what each live session is doing, from evidence only: the running command and elapsed time, the foreground process or a known CLI's name (Claude Code, Codex, Aider, …), active or quiet output, *needs attention* when the program sent a terminal notification or bell, fullscreen, the title it set, and the last command's result while idle. Nothing is guessed, and paths under your home directory are shown as `~/…`.
- **`/layout` showcase:** preview composer position (Bottom, Top, Flow) × transcript presentation (Normal, Chat) on sample content through the real renderer, then save and apply live. Also under Config → Layout. Nothing in the preview runs or reaches the transcript, journal or `/copy`.
- **Flow composer:** Config → Composer position → Flow (the command palette's Toggle composer position cycles Bottom, Top and Flow). The prompt and input follow the newest output inside NMSh's document, like a conventional terminal, and scroll with it. Typing while scrolled back returns to them; scrolling alone does not. Menus open below the input, panels pin to the bottom, and Chat presentation and fullscreen passthrough work as before.
- **Startup restore is your choice:** Config → Sessions → Startup restore (Ask, the default; Always; or Never) and Multiple detached sessions (Ask which, or Open all). With one detached session, NMSh asks: Resume, Not now, Always or Don't resume at startup. With several, a picker restores the ones you select: this window takes one, and the others open in new Ghostty, Terminal.app or kitty windows. Where a host can't open windows, NMSh names the `nmsh --attach` command for each. Never only skips restoring at launch; it never ends a session.
- **Live-session hardening:** live sessions that end while no window is attached are archived at the next launch or `/resume`, with the real exit code or a note that the service stopped or the system restarted. Output captured while detached is kept. A frontend that loses its service reports it and archives the transcript. `/resume` shows how long each idle live session has been at its prompt.
- **Exactly-once archiving:** launch recovery, Kill Session and live journal checkpoints share a cross-process lock per journal, so concurrent launches never archive a session twice or overwrite a complete archive with partial state.
- **Fullscreen reattach:** reattaching to a running fullscreen app restores the terminal modes it had turned on, including mouse reporting and bracketed paste.
- **Safe updates:** each session-service protocol version has its own socket, so live sessions owned by an older service keep running after an update. A newer frontend never touches sessions it cannot verify, and it tells you they exist.
- **Session limit:** at most 16 live sessions per service (`NMSH_MAX_SESSIONS`). When the limit is reached, a new window falls back to an in-process shell with a notice. Detached sessions are never ended to make room.

### Fixed
- **Interactive terminal UIs that draw inline** (agent CLIs such as Claude Code, including under a wrapper or alias like `claude-account2`) now get the terminal. NMSh hands over as soon as a running program turns on terminal input modes (bracketed paste, mouse, focus events or the kitty keyboard protocol), not only when it switches to the alternate screen or has a known name. Keys reach the program, NMSh's composer steps aside, no control sequences leak into the transcript, and the same applies after reattaching. Ordinary commands, including progress output, stay in NMSh.
- **Restoring several detached sessions** (the startup picker or Open all) opens every selected session again. NMSh used to exit while waiting for the first extra window to open, printing "Detected unsettled top-level await": only that window appeared, and the current window never attached. In Terminal.app this looked like `nmsh` failing to start. A window launcher that hangs now times out after 15 s, and that session's `nmsh --attach` command is named instead.
- Ctrl+Z suspends the foreground job again (raw `^Z` and the Kitty keyboard encoding), and `jobs` and `fg` work as in plain zsh.
- After Ctrl+Z, `jobs` could list a stray `suspended (tty output)` job. NMSh's own prompt hook ran `stty` as a job, and it could be stopped when it ran before zsh had taken the terminal back. The hooks now change terminal modes outside job control.
- The session service no longer crashes when a window resize races a shell's exit. node-pty could throw `EBADF` for a PTY that had just closed, which inside nmshd would have ended every live session. Other resize failures are now reported to that window instead of ending the service.
- A launch notice (for example, sessions archived while no window was attached) is no longer erased when the window reattaches to a live session.

### Removed
- `scripts/pty-history-smoke.mjs`: its checks had gone stale (it asserted retired UI text), it ran against the real config and live session service, and deterministic tests now cover everything it checked.

- **Shared panel shell:** every NMSh panel uses one temporary top boundary, title, optional tabs and search, and a context-aware key bar. Panel chrome is never stored in the transcript, `/resume`, or `/copy`.
- **Glyph compatibility choice:** first run offers Nerd Font and Safe/ASCII previews and persists the choice. It can be changed in Config → Glyph style; `NMSH_ICONS` overrides it per process. Existing v0.3 configurations keep Nerd Font styling.
- **Continuous session journal and advanced `/resume`:** the presentation session is checkpointed during use, so it survives interruption. `/resume` groups retained sessions by day, searches command text, project, cwd, and date, and navigates weeks (←/→) and months (Shift+←/→). 1000 unpinned sessions are kept by default.
- **Reusable task progress:** long-running child processes show elapsed time, a per-character travelling shimmer, factual success or failure, and bounded details (`D`/Enter). Starship's Homebrew installation uses it.
- **Starship module editor:** `/prompt` → Starship → Configure modules toggles supported modules and previews the exact lines Starship's own CLI would change. It asks for confirmation, backs up an existing `starship.toml`, and preserves comments and unrelated keys.
- **Powerlevel10k configurator handoff:** `/prompt` can run the official `p10k configure` wizard on the real terminal after backing up `~/.p10k.zsh` and `.zshrc`, and reports which files changed.
- **Update discovery and `/update`:** `/update` reports current → available with a release summary. `/update apply` fast-forwards a clean official source checkout to the verified release tag, rebuilds, verifies the build identity, and rolls back on failure; other installations get manual steps. Background checks are opt-in (Config → Update checks: Off / Daily / Weekly).

### Changed
- Connector fade defaults to Off; explicitly saved values are kept.
- Gap is stored as width 0 / 1 / 2 (Compact / Normal / Wide); legacy widths above 2 read as Wide.

### Fixed
- Compatible zsh `precmd`/`preexec` hooks from your own config (for example zoxide and Atuin) keep working inside NMSh (#16).
- A zsh prompt theme such as Powerlevel10k no longer paints its own prompt, including its right-side status, into command output.
- Esc in Prompt, Transcript, and Keyboard panels opened from `/settings` returns to `/settings`, and Esc is decoded correctly under Ghostty's Kitty keyboard protocol.

### Known limitations
- Configured-zsh completion parity and `fzf-tab` interoperability are not supported yet; NMSh uses its own completion (#52).
- Command-completion desktop notifications are not part of this release.
- Powerlevel10k: NMSh shows only its left prompt. The right prompt, gitstatus daemon, instant prompt, and settings defined only in `.zshrc` are not reproduced.
- Nested activity is limited to directly observed Node TAP v13 streams.
- `/update apply` automates only clean source checkouts of the official repository.
- Final v0.4.0 visual and interaction validation passed in Ghostty.
