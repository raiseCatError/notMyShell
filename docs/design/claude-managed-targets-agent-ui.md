# Managed Targets, agent UI, and unified mods

Status: approved by the user, including the keyboard-first amendment; implementation and disposable supported probes authorized.

## Keyboard-first amendment

Every primary workflow must be completable without a mouse: target launch/focus/picker, transcript navigation/zoom, approvals, questions, message editing, mods/extension aliases, provider-filtered inventory, search/details and any supported apply actions. A click-required workflow is incomplete. Mouse convenience is secondary; future mouse events dispatch the same semantic actions as keyboard events, never separate business logic.

Every incoming key has one explicit active owner: COMPOSER, TRANSCRIPT, PANEL, SEARCH, CHOICE, APPROVAL, AGENT_MESSAGE or PASSTHROUGH. Composer ownership preserves ordinary digits/arrows and the entire draft/cursor/selection. Printable transcript shortcuts require explicit transcript focus and an empty shell composer. Key events map to semantic actions before controller operations; a customizable keymap is out of scope, with `/keyboard` the future home.

Lists use Up/Down, Enter, `/`, Esc. Actual top tabs use Tab/Shift+Tab. Search typing filters immediately; Esc clears/leaves search first. Transcript arrows navigate/zoom, 1–5 selects available detail, Esc returns to composer; Enter only performs a safe contextual action. Approval requires a deliberate dedicated action and never ordinary Enter, typing, paste, scrolling or digits. Document deliberate differences needed to preserve existing NMSh semantics. Slash commands and ordinary-key fallbacks keep functionality accessible when terminal/OS/multiplexer intercept keys. NMSh cannot remap keys it never receives.

Mouse work is limited to correctness of existing scrolling/input and passthrough ownership. Hover, drag and pointer polish are deferred. Enable/disable is shown unavailable unless a supported, reviewed provider action exists; passive inventory does not imply activation authority.

## Intent and branch boundaries

NMSh supervises real providers and presents supported structured information. It does not replace their ecosystems or interpret their rendered terminal screens. This branch establishes the minimum target, capability, mod inventory, semantic transcript, and input foundations, with Claude as the first runtime prototype. Portable mods and provider-native extensions remain separate lanes.

This branch is based on `master` at `4f30ffd` (#328 merged) and is never merged by its author. #328's terminal ownership lifecycle (terminal-query forwarding, untranslated passthrough output, mode reconciliation), shared Tab cycling and shared display scrubber are the base it builds on: raw provider TUIs (`/nmsh raw …`) use that generic passthrough unchanged, managed Claude never does. No release, tag, version change or Homebrew work. The original audit preceded implementation and active probes. Subsequent evidence and implementation are recorded below.

## 2. Approach and Managed Target mapping

Recommended: additive interfaces around existing records and supervision. Alternative: replace sessions with a new target subsystem, at the cost of duplicate lifecycle migration. Alternative: inventory-only work, cheaper but insufficient for transcript and input requirements.

Keep `AgentSession` as the backing target record and `AgentSessions` as supervisor. Retain existing names where useful. Introduce opaque `TargetId`, an internal adapter interface, and capability facts separate from `AgentLevel`. Preserve `managed`, `attachable`, `observed`. An observed target has metadata/status only; no fabricated conversation, approval or message channel. An attachable target requires proven structured reconnection. Managed access never grants every capability.

## 4. Adapter and capability boundary

An internal `TargetAdapter` provides validated operations and supported structured events. Claude owns launch flags, handshake, protocol requests, hooks, subagent relationships, native inventory and resume semantics. Preserve useful typed Claude extensions beside normalized objects; do not flatten unknown data into invented core facts.

Initial capability names: `conversation.read`, `message.send`, `tool.observe`, `task.cancel`, `session.status`, `context.status`. Add `tool.approve` only to the human controller's adapter interface when proven. Each fact contains target id, availability (`available`, `unavailable`, `unknown`), evidence source/version, reason when unavailable/unknown, and observation/freshness timestamps where relevant. Runtime operations check facts and live lifecycle again. Help-only evidence cannot establish an available operation.

## 5. Two mod lanes, inventory, and provenance

Portable descriptors declare id, version, description, requested semantic capabilities, applicability and execution kind (`inert` or controlled built-in). Instances are keyed by `(modId, targetId, instanceId)`, with independent state, subscriptions, projections, errors and grants. The first fixture is an inert Context Meter using injected target facts, not third-party executable code.

Provider-native plugins/hooks run inside their provider under provider rules. Discovery is passive and does not grant execution or NMSh ownership. Context Packs retain their existing declarative parser/store and are projected into the same inventory.

Inventory entries distinguish identity from installation and runtime. Stable inventory keys include kind, provider, id, scope and installation reference, so identical ids across providers/projects do not collide. Store factual source, version, global/project/target scope, installedBy (`nmsh`, `provider`, `external`, `unknown`), location/reference, enabled (`yes`, `no`, `unknown`), and separately any declared permissions/integrity/signature evidence. Lack of an ownership ledger means unknown ownership, not automatically external. A known out-of-band probe fixture may truthfully be external. Hashes express integrity, never trust.

Passive discovery uses bounded supported listing/config/manifest readers with explicit freshness and partial/error states. No imports, shell sourcing, scripts, install hooks or activation. Sanitize hostile text before display. Opening the manager or explicit refresh requests one bounded refresh; no render-time I/O or continuous polling. Refresh errors preserve the last snapshot with a stale indicator. External changes appear on the next successful refresh; no external configuration is rewritten.

## 6. Broker, approval security, and isolation

The broker closes over one target/instance and exposes immutable typed results. It never returns controls, process objects, PTYs, streams, credentials, environment or arbitrary app internals. All grants default to denied and are independent. `conversation.read` grants no send, files, network, processes, secrets or other targets. Provider processes may retain provider-owned authentication; portable mods receive no environment copy.

Human approval uses a distinct controller bound to a target and pending request id. Enter, ordinary printable input, scrolling, navigation and paste never approve. Approval UI requires explicit entry and a dedicated deliberate action, checks request freshness, and records the human decision. `AskUserQuestion` becomes `CHOICE` only when its supported answer protocol is proven; it never reuses tool permission logic. Otherwise display its unavailable reason.

Portable approval vocabulary is observational (`approval.observe`, `approval.decorate`, `approval.explain`); adapter `tool.approve` is excluded from portable grants. Direct programmatic approval is out of scope. `targets.list`/`targets.aggregate` are separately explicit grants; default instances cannot enumerate others. An inert aggregation fixture can prove explicit grant behavior without making aggregation a default product feature.

No public executable loader. A worker is not a security sandbox. Provider-native executables remain outside NMSh's sandbox, and the inventory says so. Controlled fixture/controller failures mark only that instance failed. Bound state, event queues and output rates; report overflow instead of silently dropping accepted source. No initial portable filesystem/network/process capability.

## 7. Semantic source and retention

Eligible source objects include user/assistant text, tool input/result, evidenced edits/diffs, commands, choices, approvals, lifecycle/status/errors and supported typed provider extensions. Exclude hidden reasoning, raw environment/auth and undocumented internals. Preserve accepted eligible content independently of projections.

Use target-private append-only source storage with a bounded recent cache and offset-indexed lazy reads. Proposed defaults: 1 MiB recent source cache, 8 MiB individual framed event, 64 MiB target source budget. Count UTF-8 bytes. Private directories 0700/files 0600; exclusive creation, reject unsafe/symlink locations, cleanup only owned files on target disposal. Disk errors, oversized frames and exhausted budgets create explicit incomplete markers with reason; retained content stays retrievable. These are documented safety boundaries, not claims of unlimited retention. Avoid whole-spool reads. Stop accepting oversized framing safely without desynchronizing subsequent records.

Semantic projections expose meaningful available depths from 1–5: identity; factual metadata/excerpt; evidenced semantic regions; compact content/diff; full eligible content. A plain text object need not invent five structures. Select the nearest lower available depth, or minimum available if none lower. Always show actual depth and incompleteness. Preserve typed diff source only when present; never invent hunks, counts or summaries. Separate visible-copy and full eligible-copy, both plain text, with no focus feedback/chrome. Rendering never mutates source or performs discovery/storage I/O.

## 9. Unified `/mods` UX

One manager/controller in `src/agents/mods/`. `/mods` and `/extensions` open the same state. Top tabs: All, Portable, Provider-native, Context Packs. Provider filter is one secondary control, not another tab bar. Provider shortcuts set this filter on the same manager. Claude relevance includes native entries plus portable applicability/enabled target instances, visibly distinguished.

Cards show kind/provider, scope, enabled state, managed ownership, execution host, sandbox status and requested/granted capabilities. Native entries prominently state `Executes inside Claude Code` and `NMSh sandbox: No`; declarative entries say `Not executable`. Unknowns remain explicit. At narrow widths wrap risk/provenance fields rather than clipping them away. Details add source/version/reference and evidence freshness.

`/` enters local search of loaded factual metadata; Esc exits search before closing. Tab/Shift+Tab navigate actual tabs outside search; while editing search they do not silently change tabs. Arrows select results; selection follows stable inventory identity or deterministically falls back to first match. Show `No matches`, loading, stale and partial refresh states. Search never launches a shell/provider or triggers discovery.

## 10. Commands and raw routing proposal

`/claude`: select relevant targets in current shell cwd; focus exactly one live target, launch when none, picker when several. Proven resumable ended targets can participate only after adapter evidence; otherwise do not advertise reconnect. `/claude new` always launches fresh. `/claude mods` opens the shared inventory filter. Preserve `/ai` as neutral manager. `/codex` and `/codex new` use identical routing but return a truthful unavailable reason until a Codex adapter is implemented/proven; `/codex mods` can still filter known inventory. No fabricated managed Codex session. OpenCode follows the same inventory pattern when discovery is supported.

Propose `/nmsh raw claude [args]` and `/nmsh raw codex [args]`: remove only the fixed prefix and forward the remaining provider command verbatim through the existing real-shell passthrough path. Never create a managed target for this route. Raw arguments retain ordinary shell semantics; explain that distinction in help.

Bare routing, after tests and Claude proof: only a trimmed exact literal `claude` (no args/quotes/wrappers/operators/assignments) enters managed mode. Exact `codex` remains shell-native while its adapter is unavailable. Any arguments, executable paths, `command claude`, `env`, redirects, pipelines or shell lists retain normal shell execution. Existing identity detection must not be reused for interception. Aliases/functions are a conflict: managed routing should defer when shell facts identify an alias/function; if resolution is unknown, keep shell execution. Slash commands are always the unambiguous managed route. Publish this policy before enabling interception.
