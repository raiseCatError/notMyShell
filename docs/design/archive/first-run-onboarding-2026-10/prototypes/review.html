Real Aurora

  • The screensaver's own engine, renderScene('aurora'), drawn into a reused CellGrid. No second animation engine.
  • Theme-aware sky: an aurora's green rim and blue glow with the theme's accent in the upper curtains, over the theme's own night.
  • A switches Aurora on, Subtle or Off and saves it in onboardingBackdrop; a new Settings row offers the same switch later.
  • After a minute without a key the sky settles to a still frame, and the next key wakes it.

Calm by rule

  • Reduced Motion: one still frame and no clock. NO_COLOR, Effects Off and 16-color terminals turn the sky off.
  • Light never sits behind text. Only the sky and deliberate fills paint backgrounds, so transparent terminals stay transparent everywhere else.
  • Keys work from the first frame; no intro to wait through.

Sharp, keyboard-first

  • NMSh's own powerline geometry for selection (notch, fill, wedge), half-block buttons, square keycaps. No rounded corners.
  • 1–4 jump, ⏎ reviews, ⏎ again applies. esc steps back, and from the top asks Leave setup? with Stay focused.
  • Nothing applies because it is highlighted.

Recommendation

Build Horizon, lit like Stage, ending like First Prompt

Horizon is the only direction that shows all four starting points and their consequences at once, keeps light away from text, scales cleanly to small and short terminals, and has a bounded cost. Stage makes the most beautiful single frame, but it hides three choices at any moment and costs the most to build and run. First Prompt is the most honest, but it asks the transcript to carry a decision that deserves its own moment.

  1. Take Stage's lighting. Horizon's sky follows the highlighted choice: vivid for Recommended, a calm still night for Minimal, a spectrum for Customize, and for Keep Existing it goes out, leaving the bare horizon. One palette cross-fade on the same engine, and the difference between the four is felt as well as read. Captures below come from the prototype with this switched on.
  2. Take First Prompt's ending. After Apply, setup folds into one receipt line in the transcript (Started with NMSh Recommended · /startup changes it anytime) and the welcome carries on there. Minimal and Keep Existing end on the receipt alone.

Discard

  • The centered 56-column rounded box and the dialog-over-wallpaper composition
  • The static hand-rolled gradient (backdropColor, BACKDROP_PALETTES)
  • Equal-weight list rows with a › pointer and text-heavy notes
  • Docs / bug / feature keys on the selector (they stay in /help)
  • esc in review jumping straight to Leave setup?

Keep

  • One selector state and draft (quickDraft, review before Apply)
  • introSeen once-only semantics and Stay-first leave confirmation
  • Customize returning to the selector; onboardingBackdrop
  • The retained intro and preview engines, still never invoked automatically

Add

  • The real Aurora engine with moods, and the A switch
  • Keep Existing with read-only detection
  • /startup, the transcript receipt and the one-time welcome
  • The guided setup restyled in the same language
Keep Existing

Keep your look, add NMSh's features

What follows comes from reading the shell adapters, provider adapters and configuration code on this branch. Nothing in it is implemented yet.

How NMSh works today shapes everything here. It runs your real shell and sources your own startup files, so aliases, functions, PATH and plugin hooks survive. It also owns line editing (ZLE off, Bash --noediting) and blanks the shell's own prompt every cycle (PROMPT/RPROMPT, PS1, fish_prompt). Prompts reach the screen only through NMSh's adapters.

Preserved exactly

  • Terminal host appearance: palette, background, font, transparency, cursor. Keep Existing writes no host config and enables no managed cursor shader.
  • Your shell and its startup files: zsh (.zshenv, .zprofile, .zshrc), Bash (system and ~/.bashrc), Fish (config.fish).
  • Aliases, functions, environment and non-UI hooks (zoxide, Atuin, direnv).
  • starship.toml, ~/.p10k.zsh, Oh My Posh configs and tool themes: read, never written.
  • Saved NMSh preferences on an already-configured install.
  • Theme Bridge stays independent.

Through an existing adapter

  • Starship: starship prompt with your config. Multi-line prompts are flattened to one line and the right prompt is not drawn. Today the flattened line also ends with Starship's own ❯ above NMSh's marker; Keep Existing would drop that trailing character (a small adapter change).
  • Powerlevel10k: an isolated zsh -f helper with your theme and config. gitstatus is off (vcs_info fallback), the right prompt is not drawn, and instant and transient prompts do not apply.
  • Oh My Posh: oh-my-posh print primary; remote configs are never fetched.
  • zoxide, Atuin, fzf, Television and fetch welcomes through NMSh's provider adapters.

Not reproducible today

  • Custom prompts: PS1/PROMPT, Oh My Zsh themes other than p10k, pure, spaceship, Fish fish_prompt, Tide.
  • ZLE and readline behavior: custom widgets, vi-mode, zsh-autosuggestions, zsh-syntax-highlighting. NMSh's composer, suggestions and syntax colors stand in.
  • Right, transient and async prompt features.
  • Banners your rc prints at startup (suppressed while NMSh boots; a Welcome provider can bring fastfetch back).
  • NMSh chrome in your terminal's exact palette: no ANSI-indexed chrome or palette query exists yet.

Custom prompts: an honest path

  • Detect it with evidence and say so: NMSh can't draw custom prompts yet. What should it show?
  • Default to Composer only (Prompt None): nothing imitates yours, and your prompt keeps working everywhere outside NMSh. NMSh Minimal is offered by name, never substituted.
  • Proposed adapter, Your prompt, captured: just before NMSh blanks the prompt, the managed shell expands it and reports it over the existing OSC 777 channel. zsh expands PROMPT as the p10k helper already does; Bash 4.4+ uses ${PS1@P} (macOS Bash 3.2 cannot); Fish keeps a copy of your fish_prompt and calls it. Limits: no async repaint, no right prompt at first, multi-line flattened, control sequences stripped. It is opt-in and labeled experimental. It runs only your own prompt code in your own shell, never as a way to discover anything.

  1. An already-configured NMSh keeps its chosen provider. Keep Existing changes nothing unless you ask it to re-detect my terminal setup, which shows a reviewed diff.
  2. Fresh install with exactly one active prompt (started by your rc and runnable): keep it.
  3. More than one active: ask which. One prompt runs at a time.

Three things stay separate. Starting point is one small label saved on Apply, used only so /startup can say Current: Keep Existing. Effective configuration is the normal config, the only source of truth. Detected environment is computed when the selector opens, shown with its evidence, and never saved. No preset snapshot is stored to drift away from the real settings.

/startup

One selector, two doors

  • Nothing to collide with. No /startup command or alias exists in slashCommands.ts, the parser, help, docs or the palette. The word appears only in the Live session startup setting and the startup progress panel, neither of which is a command. /presets and nmsh --preset/--presets are separate and stay untouched.
  • Exact parsing. The parser already matches commands with anchored patterns (/^\/presets\s*$/). /^\/startup\s*$/ routes to the same state as /setup quick, sharing rendering, review, confirmation and Apply. No /preset.
  • Discoverable everywhere. Slash suggestions, the palette, /help, the README, Settings (Choose a preset becomes Starting point · /startup) and Setup Cat's header and Start step.
  • First run is not reopening. The first-use welcome plays only on a genuine first run (!onboardingComplete && !introSeen) after Recommended. /startup and /setup quick never replay it.
  • Reopening is safe. Highlighting applies nothing. Review lists the real differences from your current settings and says when a choice replaces customized presentation. Custom themes and gradients survive unless you approve replacing them. Shell, provider, queue and integrations change only through Keep Existing's explicit re-detect.
Defaults & welcome

The requested defaults, and the first hello

Minimal

  • Two-line by default, One-line on the same control: the default argument of minimalPromptConfiguration and the selector's initial layout.

Cursor

  • Effects Off in the canonical fresh and Recommended configuration.
  • Choosing Fire defaults to the Classic orange gradient; Purple, Blue, Green, Follow theme and Custom remain.

Legacy

  • Saved or imported explicit cursor settings and custom gradients survive normalization unchanged. Only missing fields take defaults, as the existing migration policy requires.
  • Where it lives. In the transcript, after Recommended on a first run only. It is never a splash screen.
  • What it says. You're all set. Welcome to notMyShell! · We're so glad you're here. Your shell is still yours; NMSh just makes it a nicer place to live. Then four things to try: /guide, /btw, F1, /startup. It closes with The aurora lives on in /screensaver.
  • How it moves. The Vespyr welcome block blinks and flicks its tail, a short gradient rule keeps the horizon's light, and lines arrive in under 600 ms with one light sweep on the headline. Under Reduced Motion it appears complete.
  • Quiet paths stay quiet. Minimal and Keep Existing get the receipt line and nothing else.

Limits

What this review does not show

  • Captures come from xterm.js through VHS at an 18px font. Ghostty's glyph drawing and metrics differ slightly, and at your usual font size the Aurora's pixels are finer. The live prototype in Ghostty is the real check.
  • Keep Existing evidence in every frame is a fixed, fictional sample. Nothing on this Mac was read.
  • Detection, neutral chrome for Keep Existing, Terminal palette chrome and the shell-prompt adapter are proposals. None exist yet.
  • Prototype code is throwaway and never joins the branch. Production work starts after approval: an updated spec and acceptance criteria, tests first, then the implementation.
