## Implementation and compatibility

Build temporary output-start, disclosure-end and source-start indexes once per presentation. First entries preserve the previous array priority, including duplicate anchors and out-of-order records. A running minimum array index advances before folded-range skips, preserving the original first-match row metadata. No completed-record order, ownership, semantic/fold behavior or stored bytes change. No persistent transcript cache is added.

Sample authored-color policy once per synchronous presentation and pass it through wrapping. Raw-only presentations do not query that policy; standalone sticky rendering still samples fresh policy. Between-frame color changes and original raw PTY SGR remain covered. The deterministic policy test failed at 100 reads per 100 authored lines before this change, then passed at one per frame (zero for raw-only).

A separate full-row comparison checks ANSI/plain text and **every** row metadata field against unchanged dev across 5,000-record and mixed/context/fold/compiler fixtures, Normal/Chat layouts, 40/80 columns and truecolor/None. Serialized transcript data must also remain identical. [Passed comparison hashes](history-equivalence-accepted-20261025.json). The timing harness's arithmetic checksum is only a lightweight guard; the deep comparison is the byte/metadata equivalence evidence.

## Regression controls and rejected experiment

`addHistoryLine` creates NMSh-authored metadata with word wrapping and visual gaps. Its 100k-row control improved ~330 → 102 ms with retained benchmark heap essentially unchanged (~227 MiB). This is **not** raw PTY throughput. [Original authored control](authored-baseline-transcript-20261025.json), [candidate](authored-history-candidate-transcript-20261025.json).

A separate control writes actual program bytes and asserts no authored line types. Original/repeated original 100k wrap medians were 86.24 / 85.90 ms; accepted candidate 87.13 ms. Resize was 84.63 / 77.86 ms in controls versus 81.67 ms candidate. At 10k rows, candidate wrapping was ~1.1 ms slower (6.83 versus 5.67 / 5.72 ms); this small absolute regression is retained here. Retained benchmark heap stayed essentially equal (~221 MiB at 100k). These are component-process measurements, not application idle/peak memory claims. [Original raw control](pty-baseline-transcript-20261025.json), [candidate](pty-history-candidate-transcript-20261025.json), [repeated original](pty-baseline-repeat-transcript-20261025.json).

An attempted empty-index conditional fast path worsened the 100k raw wrap/resize measurements to ~98 / 106 ms and was **reverted**. Its small patch and raw samples remain in the dedicated external evidence directory. The accepted source keeps the simpler unconditional lookups. Earlier full-line caching and automatic compile-cache experiments were also rejected for their measured tradeoffs; neither is in this PR.
