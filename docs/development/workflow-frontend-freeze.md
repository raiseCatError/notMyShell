## Implemented behavior and verified shell semantics

Input startup/readiness, hidden/function/key reads, raw/fullscreen handoff and detach/reattach retain the persistent real shell. Fish reader ownership uses authenticated evidence; Fish multiline submission uses native `begin`/`end`, while zsh/Bash use brace groups. Parse-only Fish checks do not execute prepared commands. Foreground cwd is authoritative at submission; asynchronous context may catch up later. Native completion framing accepts fragmented LF/CRLF readiness within its existing bound and budgets.

The queue owns exact entries and dispatches one at a time only at authenticated readiness, preserving cwd, variables, functions and multiline meaning. Taking an entry and clearing readiness prevent duplicate dispatch. Plain failure pauses by default; an explicit `always` condition may continue after plain failure, never interruption. Approval belongs to exact text/condition and edits withdraw it. Shell switching pauses; shell exit drops entries instead of replaying them elsewhere. Silence is never completion.

Copy selection, sticky/block controls and folding preserve stored output, selection and FOLLOW/DETACHED behavior. `/copy` remains plain text without NMSh presentation chrome. NO_COLOR suppresses restored NMSh-owned styling without changing raw program SGR or stored bytes. Copy as Report and comparison `r` report exports review the exact text; source sanitization/redaction precedes Markdown enclosure, toggles use stable snapshots, edits are rescanned, short panels refuse unreachable approval, and cancellation preserves the clipboard. Comparison `c` instead copies the sanitized plain diff directly, without the report-review/redaction gate; it can contain secrets and shows a caution when the pattern detector flags them. Plain `/copy` also retains its intentional unredacted semantics. Writer completion requires error-free payload delivery and backend exit zero while retaining size, timeout, EPIPE and owned-process cleanup gates.

Vocabulary preserves factual lifecycle status and stable live choices across detach/reattach. References, staging, recorded-cwd pins, recipes, failure navigation and queue conditions reuse stored results through explicit actions. Preserving/recalling a draft never executes it; submitting the original draft leaves action-menu/command focus and submits once. Clips remain bounded frontend memory. Clipboard suggestions are off by default; macOS idle observation reads metadata only and Linux fails closed without a supported metadata-only counter. Module diagnostics reuse collection/cache/provenance snapshots and do not start collectors merely by opening details.

## Stable command-submission and focus boundaries

The typed [SessionClient](../../src/session/SessionClient.ts) is the shell boundary. Subscribe before `start()`. `submit(command)` submits shell text; `write(data)` is program input; `interrupt()` and `endInput()` preserve foreground control; `resize(columns, rows)` follows shared geometry. `kill()` ends the shell; `detach()` preserves service sessions but ends in-process shells. `ack(seq, journalId)` acknowledges durable stream receipt, not command success. `switchShell(shell, cwd)` waits for spawn, with readiness arriving separately. Negotiate optional `features` before using queue/conditions on an older service. Session identifiers are identity, not credentials.

`TerminalApp.routeComposer('enter' | 'queue' | 'send')` and `submit(realShell, skipInstallCheck)` remain **private implementation seams**, not a plugin API. Queue composition/editing has first claim; recognized slash controllers retain their own rules; foreground replies/direct input precede ordinary queue/direct-shell submission. Ctrl+Q composes a queue entry and Ctrl+S sends to the foreground program. A future background action must not bypass review, steal startup/hidden/key/fullscreen input, intercept queued dispatch, or create a normal foreground transcript record. No background-submission interception is connected here.

Panels, approval/review, pickers, search and agent input preserve their existing focus ownership before ordinary composer/history routing. Session polling preserves stable selected identity, query, draft and focus; failed polls retain the last validated view and a valid empty response clears it. `screenPlan.ts`/`planFrame` remain the single geometry path for rendering, hit testing, cursor, viewport and PTY size. Frontend chrome never becomes transcript output.
