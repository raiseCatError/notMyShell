# Architecture findings and recommended direction

## Slice 2 rulings (Kitty native shaders, 2026-10-28)

- NMSh generates its OWN pipeline file (absolute path under NMSh's config folder) rather than naming shipped pipelines: each preset's shipped group structure (events, curve, step, textures, attach, output) is copied from the installed resource, and shipped pipeline-level vars move into each group. NMSh never emits pipeline-level vars (Kitty would apply them to the user's shaders). User pipeline-level vars that would leak into NMSh's groups are pinned back to the shipped source literal inside NMSh's groups.
- One NMSh-owned `custom_shaders` line holds the user's effective value VERBATIM (raw text, original quoting) plus NMSh's quoted pipeline path, after (default) or before it. A simulation through the real configuration graph must show that exact list as effective, from NMSh's fragment, or the plan is refused. Earlier shadowed lines are disclosed, not refused (Kitty's semantics are deterministic).
- Refuse (no write) when preservation or safety cannot be established: dynamic includes, Kitty launch overrides (`-o custom_shaders|cursor_trail`, `--config`; `ps` of KITTY_PID and `macos-launch-services-cmdline`; unreadable launch state also refuses), unbalanced quoting/control characters, user pipelines that are unreadable/unparseable/outside home, a user `.slang` that would replace a shipped shader NMSh tunes, named-texture overlap, a second cursor trail, more than 16 groups, an unrecorded or duplicated hook, edited/unowned NMSh files. A user entry Kitty cannot find is kept as written with a note (Kitty already skips it).
- Drift: the ledger records the user's value composed with. If it changes later (Kitty keeps loading NMSh's reviewed copy), the studio says so and sync refuses; a new review recomposes. This is the unavoidable cost of Kitty's single value; it is disclosed rather than hidden.
- Parameters: NMSh curates labels and SAFE bounds; a parameter is offered only if the installed shader declares it with the expected type and a literal default (the shipped pipeline's own value wins). Values are validated, never clamped at plan time. Presets without exposed constants say so.
- Gates: Reduced Motion and Decorative Effects Off write nothing new and, after setup, sync removes every NMSh group (the fragment then sets no custom_shaders, so the user's own value applies). A Portable cursor renderer removes NMSh's Kitty trail group. Sync rewrites only NMSh-owned files after the reviewed setup, mirroring the existing /cursor managed-file contract, and refuses on drift.
- One cursor engine: /cursor still decides whether there is a trail (Motion) and its color; the Kitty studio decides Kitty's trail style. A written Kitty trail shader makes Kitty native own the trail (Portable skips motion); the Lightning trail also owns the Lightning effect. Fixed an existing bug: NMSh's Kitty cursor fragment kept `cursor_trail 3` with the Portable renderer (two trails).
- First offered presets: Default/Blaze/Lightning/Motion-blur trails (one at a time), Northern Lights, Matrix, Fireworks, Pond Ripple, Spotlight, Focus highlight, Dim inactive windows (exclusive with Focus highlight: same shader), Tab change, CRT (opacity note). Other installed pipelines are listed as "installed, not offered yet".

The human explicitly approved this implementation direction and waived the design-document approval gate. Recommendations below guide implementation; meaningful trade-offs are recorded here.

- Reuse PromptConfiguration and current canonical editors. AppearanceHub launches canonical editors, not copies. Extend cursor/native and existing host integration rather than create contradictory persistence.
- First repair existing Ghostty appearance: readGhosttySettings returns fabricated constants, saveGhosttySettings silently appends an include and overwrites a fragment. These cannot be reused unchanged for the requested safety contract. Reuse inspected Theme Bridge ownership/verified-edit patterns where applicable; further audit required.
- Host capability is separate from implemented NMSh presets and loaded-state evidence. Kitty's old backend exposes only tail; broadening it must accompany actual generator support and version/catalog checks, not capability advertising alone. Unknown versions fail closed for new features.
- Kitty pipeline compiler and Ghostty GLSL compiler share logical settings only. Validate composition, parameters and dependencies, preserve pre-existing shaders/includes, disclose unresolved effective values rather than invent defaults. Native adoption is explicit; native and Portable overlap must be suppressed, including pending reload state.
- Audit loaded-vs-written integration state. A written fragment does not prove a renderer loaded it. Switching Portable/reduced-motion cannot be claimed effective while old host shader remains loaded. Manual reload/restart status must remain visible and ambiguous overlap must not be painted twice. Further design needed for safely managing surface-wide native lifetime across fullscreen handover without per-event reload.
- NMSh already has a semantic Transition union, per-event look/timing, cancellation, deterministic paints and PresentationClock. Extend these, not an independent scheduler/event engine. Clean/Rich controls and Chroma palette remain canonical. Terminal-wide shader events are not NMSh widget events. Do not use BEL as a command-success channel (audible/unrelated side effects), magic pixel markers, remote arbitrary-window updates or per-event config rewrites.
- Use existing GraphicsService and ImageSurface typed builders/owner cleanup for welcome. External capture remains SGR-only; never forward captured APC/OSC/DCS/raw output. Current GIF is first-frame-only; animation requires bounded actual frame decode/composition, disposal/timing and native upload/control extensions. APNG support likewise is work, not a flag.
- Full-terminal P preview and startup share one welcome composition and sequencing service. Preview lifecycle acquires alternate screen/input, releases owned graphics on every exit and restores draft/selection. No session recreation or startup shell execution. Static final snapshot belongs to transcript; animation frames/bytes do not.
- Read Fastfetch JSONC as bounded data; never execute Neofetch shell config to discover logos. Only literal recognized assignments can be imported. Dynamic sources/includes require truthful unsupported guidance. Existing provider execution contract is distinct from safe new static system-info fields.
- New fields may use only explicit typed facts/static text, no automatic shell commands. Sensitive hostname/path/Git facts opt-in; presets omit private asset bytes/paths unless explicitly exported. Original assets are immutable.
- Proposed implementation bounds (builder decisions, not agreed): <=8MiB welcome asset input, <=2MP source, <=320x240 animation canvas, <=75frames, <=15fps, <=5seconds per startup playback, <=32MiB decoded animation data, bounded cache within existing GraphicsService budget. Validate both frame count and total bytes before allocating; unsupported/over-budget assets get deterministic still fallback or actionable refusal. Existing general viewer limits remain unchanged. No AI segmentation claims or new dependency without justified need.
- Independent PR slices required. Do not combine whole program into one feature PR. All required features remain in scope; unsupported native semantic targeting has production Portable fallback as explicitly requested.

Ruling: Ghostty version-tagged source loads legacy config before preferred config.ghostty, then all recursive includes via a global appended queue after every default root; documentation overview is ambiguous. Implement source order and simulate proposed fragments, refusing a later nested-include conflict. Treat unresolved theme-derived fields as unknown rather than defaults. Dynamic includes and external/symlinked config roots are conservatively blocked in this slice.

Ruling: preserve the existing Theme Bridge ledger design concept but isolate host ownership records; Theme Bridge targets and current write primitives do not provide this transaction/dependency contract. Use exclusive staging, captured file identity/content, checks before staging and immediately before rename, and rollback of only unchanged task writes. POSIX rename is not atomic compare-and-swap; do not claim protection against arbitrary concurrent malicious directory swaps. Group/world-writable paths are refused.

Ruling: preserve valid unchanged numeric blur above the normal UI range during unrelated saves. Require nonnegative safe integers in generated data; UI normally caps increases at50 but can decrease a larger existing value incrementally. Display bars clamp without changing stored values.
