# Architecture findings and recommended direction

## Slice 2 rulings (Kitty native shaders, 2026-10-28)

- NMSh generates its OWN pipeline file (absolute path under NMSh's config folder) rather than naming shipped pipelines: each preset's shipped group structure (events, curve, step, textures, attach, output) is copied from the installed resource, and shipped pipeline-level vars move into each group. NMSh never emits pipeline-level vars (Kitty would apply them to the user's shaders). User pipeline-level vars that would leak into NMSh's groups are pinned back to the shipped source literal inside NMSh's groups.
- One NMSh-owned `custom_shaders` line holds the user's effective value VERBATIM (raw text, original quoting) plus NMSh's quoted pipeline path, after (default) or before it. A simulation through the real configuration graph must show that exact list as effective, from NMSh's fragment, or the plan is refused. Earlier shadowed lines are disclosed, not refused (Kitty's semantics are deterministic).
- Refuse (no write) when preservation or safety cannot be established: dynamic includes, Kitty launch overrides (`-o custom_shaders|cursor_trail`, `--config`; `ps` of KITTY_PID and `macos-launch-services-cmdline`; unreadable launch state also refuses), unbalanced quoting/control characters, user pipelines that are unreadable/unparseable/outside home, a user `.slang` that would replace a shipped shader NMSh tunes, named-texture overlap, a second cursor trail, more than 16 groups, an unrecorded or duplicated hook, edited/unowned NMSh files. A user entry Kitty cannot find is kept as written with a note (Kitty already skips it).
- Drift: the ledger records the user's value composed with. If it changes later (Kitty keeps loading NMSh's reviewed copy), the studio says so and sync refuses; a new review recomposes. This is the unavoidable cost of Kitty's single value; it is disclosed rather than hidden.
- Parameters: NMSh curates labels and SAFE bounds; a parameter is offered only if the installed shader declares it with the expected type and a literal default (the shipped pipeline's own value wins). Values are validated, never clamped at plan time. Presets without exposed constants say so.
- Gates: Reduced Motion and Decorative Effects Off write nothing new and, after setup, sync removes every NMSh group (the fragment then sets no custom_shaders, so the user's own value applies). A Portable cursor renderer removes NMSh's Kitty trail group. Sync rewrites only NMSh-owned files after the reviewed setup, mirroring the existing /cursor managed-file contract, and refuses on drift.
- One cursor engine: /cursor still decides whether there is a trail (Motion) and its color; the Kitty studio decides Kitty's trail style. A written Kitty trail shader makes Kitty native own the trail (Portable skips motion); the Lightning trail also owns the Lightning effect. Fixed an existing bug: NMSh's Kitty cursor fragment kept `cursor_trail 3` with the Portable renderer (two trails).
- First offered presets: Default/Blaze/Lightning/Motion-blur trails (one at a time), Northern Lights, Matrix, Fireworks, Pond Ripple, Spotlight, Focus highlight, Dim inactive windows (exclusive with Focus highlight: same shader), Tab change, CRT (opacity note). Other installed pipelines are listed as "installed, not offered yet".

The human explicitly approved this implementation direction and waived the design-document approval gate. Recommendations below guide implementation; meaningful trade-offs are recorded here.

- Reuse PromptConfiguration and current canonical editors. AppearanceHub launches canonical editors, not copies. Extend cursor/native and existing host integration rather than create contradictory persistence.
- First repair existing Ghostty appearance: readGhosttySettings returns fabricated constants, saveGhosttySettings silently appends an include and overwrites a fragment. These cannot be reused unchanged for the requested safety contract. Reuse inspected Theme Bridge ownership/verified-edit patterns where applicable; further audit required.
- Host capability is separate from implemented NMSh presets and loaded-state evidence. Kitty's old backend exposes only tail; broadening it must accompany actual generator support and version/catalog checks, not capability advertising alone. Unknown versions fail closed for new features.
- Kitty pipeline compiler and Ghostty GLSL compiler share logical settings only. Validate composition, parameters and dependencies, preserve pre-existing shaders/includes, disclose unresolved effective values rather than invent defaults. Native adoption is explicit; native and Portable overlap must be suppressed, including pending reload state.
- Audit loaded-vs-written integration state. A written fragment does not prove a renderer loaded it. Switching Portable/reduced-motion cannot be claimed effective while old host shader remains loaded. Manual reload/restart status must remain visible and ambiguous overlap must not be painted twice. Further design needed for safely managing surface-wide native lifetime across fullscreen handover without per-event reload.
- NMSh already has a semantic Transition union, per-event look/timing, cancellation, deterministic paints and PresentationClock. Extend these, not an independent scheduler/event engine. Clean/Rich controls and Chroma palette remain canonical. Terminal-wide shader events are not NMSh widget events. Do not use BEL as a command-success channel (audible/unrelated side effects), magic pixel markers, remote arbitrary-window updates or per-event config rewrites.
- Use existing GraphicsService and ImageSurface typed builders/owner cleanup for welcome. External capture remains SGR-only; never forward captured APC/OSC/DCS/raw output. Current GIF is first-frame-only; animation requires bounded actual frame decode/composition, disposal/timing and native upload/control extensions. APNG support likewise is work, not a flag.
- Full-terminal P preview and startup share one welcome composition and sequencing service. Preview lifecycle acquires alternate screen/input, releases owned graphics on every exit and restores draft/selection. No session recreation or startup shell execution. Static final snapshot belongs to transcript; animation frames/bytes do not.
- Read Fastfetch JSONC as bounded data; never execute Neofetch shell config to discover logos. Only literal recognized assignments can be imported. Dynamic sources/includes require truthful unsupported guidance. Existing provider execution contract is distinct from safe new static system-info fields.
- New fields may use only explicit typed facts/static text, no automatic shell commands. Sensitive hostname/path/Git facts opt-in; presets omit private asset bytes/paths unless explicitly exported. Original assets are immutable.
- Proposed implementation bounds (builder decisions, not agreed): <=8MiB welcome asset input, <=2MP source, <=320x240 animation canvas, <=75frames, <=15fps, <=5seconds per startup playback, <=32MiB decoded animation data, bounded cache within existing GraphicsService budget. Validate both frame count and total bytes before allocating; unsupported/over-budget assets get deterministic still fallback or actionable refusal. Existing general viewer limits remain unchanged. No AI segmentation claims or new dependency without justified need.
- Independent PR slices required. Do not combine whole program into one feature PR. All required features remain in scope; unsupported native semantic targeting has production Portable fallback as explicitly requested.

Ruling: Ghostty version-tagged source loads legacy config before preferred config.ghostty, then all recursive includes via a global appended queue after every default root; documentation overview is ambiguous. Implement source order and simulate proposed fragments, refusing a later nested-include conflict. Treat unresolved theme-derived fields as unknown rather than defaults. Dynamic includes and external/symlinked config roots are conservatively blocked in this slice.

Ruling: preserve the existing Theme Bridge ledger design concept but isolate host ownership records; Theme Bridge targets and current write primitives do not provide this transaction/dependency contract. Use exclusive staging, captured file identity/content, checks before staging and immediately before rename, and rollback of only unchanged task writes. POSIX rename is not atomic compare-and-swap; do not claim protection against arbitrary concurrent malicious directory swaps. Group/world-writable paths are refused.

Ruling: preserve valid unchanged numeric blur above the normal UI range during unrelated saves. Require nonnegative safe integers in generated data; UI normally caps increases at50 but can decrease a larger existing value incrementally. Display bars clamp without changing stored values.

## Slice 3 rulings (Ghostty native shaders, 2026-10-28)

- NMSh writes its OWN GLSL (GPL-3.0-only, original code) generated from validated settings; no third-party shader is copied or downloaded. Seven presets: Smear and Comet trails (one at a time), Aurora (background-only tint), Dim when unfocused, Vignette, Scanlines, Text glow. Every parameter is compiled in as a constant and a test proves each one changes the source. Values are validated, never clamped.
- Version gates come from the uniforms each generated shader actually reads (scanned, comments stripped), against a table verified byte-for-byte: 1.2 = cursor uniforms; 1.3/1.4 add focus, cursor style/visibility and terminal colors (identical prefix in 1.3.0, 1.3.1, 1.4.0). No reported version (tmux, ssh: *hidden*), <1.2, or anything newer than 1.4.x (an unverified interface) fails closed for new setup. Sync substitutes the version recorded at review only when the running version is hidden; a running version known to be unsupported makes sync remove NMSh's passes and say why.
- Composition: Ghostty's custom-shader list is append-only and NMSh's fragment is an optional include (`config-file = ?…`) appended to the effective root file, so NMSh's passes run after every pass in the person's root files. NMSh never writes a `custom-shader =` reset, never re-lists or reorders the person's passes, and never sets `custom-shader-animation` (the older /cursor fragment did; the studio only reads and discloses it). A simulation of the whole configuration graph must show the person's passes unchanged and in order and NMSh's passes present in order, or the plan is refused (e.g. a later include that clears the list).
- Placement: Kitty's Before/After choice has no Ghostty equivalent without re-listing the person's passes (which would make NMSh own lines it did not write); Ghostty always runs NMSh's passes after. Disclosed in the studio.
- Never two trails: a trail pass refuses when any of the person's shaders reads the cursor-change uniforms, or when one cannot be read (outside the home, symlink). NMSh's older /cursor Ghostty shader is paused (its own managed file, exact content checked) while a studio trail is written; the ledger records `legacyPaused`, and the reviewed removal resumes it inside the same transaction only if the file still holds exactly the paused content and /cursor's settings still want it (otherwise the review says it is left alone). The studio never calls /cursor's writer outside its transaction. Cursor backends: a written studio trail makes Ghostty draw Smear/Tail and Portable draw effects.
- Reload: Ghostty never reloads its config by itself and NMSh never signals it. A trail NMSh stops writing (Portable chosen, motion off, Reduced Motion, removal, the older /cursor shader paused) is recorded as pending; while pending, Portable draws no cursor motion (and no effects if the older /cursor shader drew them) so a not-yet-reloaded Ghostty trail is never doubled. Pending trails accumulate across changes until a reload (legacy → Smear → Comet keeps the older /cursor shader, and its effects, pending). Pending clears when the person presses L in the studio, or when the Ghostty process found among NMSh's parents started after the change. If the record cannot be saved, the controller keeps it in memory for this process. A studio trail still written while Portable is chosen (a refused update) also suppresses Portable motion.
- Launch: the Ghostty process among NMSh's parents is read (one bounded `ps`); `--custom-shader`, `--config-file`, `--config-default-files` on its command line refuse. Not finding Ghostty (tmux, ssh, session service) is a disclosed note, not a refusal (GUI launches carry no flags).
- Architecture: TerminalApp must not mention host products (existing guard test). All Ghostty wiring lives in `src/appearance/glslStudio.ts`; the Kitty panel and the Ghostty panel are one shared `ShaderStudioPanel` with host wording supplied per host. The footer wraps with the shared `renderControlRows`.
- Sync: gate changes rewrite only NMSh-owned files; removing passes never waits for review; adding reviewed passes back re-simulates. Inside tmux (hidden version) sync uses the version recorded at review, so it never strips passes for an unrelated reason. NMSh also syncs once at startup (no process-table read), so gate changes made while it was not running (OS Reduced Motion, an edited config) reach the written passes.
- Animation disclosure: Ghostty runs its animation loop whenever any custom shader is listed (focused surface by default; `always` = every surface; `false` = only on terminal updates). Every plan discloses this; no preset claims to redraw "only while it fades".

## Slice 4 rulings (render routing and Chroma-driven native colors, 2026-10-28)

- One animation model: `Transitions`/`MotionGate` (NMSh rows) and `chooseBackend` (cursor) stay the only decision makers. `src/motion/renderRouting.ts` is a read-only view that reports, per semantic surface, whether the host GPU, NMSh's Portable renderer or nothing draws it, and why. It never schedules or draws.
- Native routing only where the host gives reliable targeting: the cursor (cursor uniforms, via the cursor backend) and whole-window focus/display passes that NMSh wrote (Ghostty ledger / Kitty ledger, hook present). Prompt transitions, command feedback, notifications, idle and welcome are always Portable or off: a terminal shader sees the whole window, not NMSh's rows. No per-widget GPU claim.
- Gates are applied as the app applies them: Effects Off, Reduced Motion and no color switch NMSh rows and Portable cursor drawing off; Settings › Motion rows set to Off are off; cursor effect None and motion Off are off; screen-mode screensavers do not start by themselves under Reduced Motion. A native trail under a gate is reported with "NMSh removes its host shader on the next sync".
- Written ≠ loaded: native focus/display routes say "written; the host loads it on its next config reload".
- `/appearance › Effects routing` shows the routes (refreshed on entering the hub or the view; no polling). The host-specific reads live in `src/appearance/nativePasses.ts`; TerminalApp stays host-neutral.
- Chroma: Ghostty Aurora gains Colors = Follow Chroma (default) / Custom. Follow Chroma uses the idle visuals' resolver (`idleStops(config, 'appearance')`: Chroma palette, or the theme while Chroma is off), its first and last stops. A Chroma or theme settings change re-syncs NMSh's Ghostty passes (only NMSh-owned files, only when the generated source differs); never per event; Ghostty applies it on its next reload. Aurora settings saved before the choice existed and carrying their own colors keep them (Custom).

## Slice 5 rulings (Shader Studio UX and previews, 2026-10-28)

- The shared studio (Kitty and Ghostty) shows a preview of the selected preset: a small sample terminal drawn by NMSh in cells (`src/appearance/shaderPreview.ts`), labelled "approximate, drawn by NMSh; <host>’s GPU shader is the real effect". It is never presented as host output.
- Families with a faithful approximation: cursor trails, aurora/northern lights, focus dim, vignette/spotlight, scanlines/CRT/TFT, glow/bloom. Others (fireworks, rockets, matrix, water, underwater, negative, ripple, tab change) say there is no preview instead of guessing.
- A run plays once on selection or value change and P replays; the app subscribes the shared presentation clock only while a run animates (`previewBusy`), never an idle loop. Reduced Motion / Effects Off draw one still frame; without color there is no preview. Short windows drop the preview rather than cutting the list or controls.
- Kitty catalog completed with the remaining shipped effects: CRT (blue), Rockets, Bloom, TFT pixels, Water, Underwater, Negative. Parameters only where the shipped shader declares them (verified against Kitty 0.49.2 sources and by the installed-Kitty live test); Underwater/Negative have none.
## Slice 6 rulings (Welcome Studio, 2026-10-28/29)

- Implemented by a delegated agent (Codex gpt-6.1-sol) in two parts (6a, 6b) and accepted by the lead after independent reviews; delegate reports: evidence `slice6/REPORT-6a.md`, `REPORT-6b.md`.
- Compatibility: `welcome` stays the provider id; `welcomeStudio` holds the native layout and `welcomePresets` up to 12 named layouts. An absent, unreadable or missing configuration keeps the historical card exactly (`customized: false`); only an explicit Studio save/preset/reset selects the native layout. Saving applies at the next start (or `/clear`).
- Privacy: fresh layouts show OS, shell and NMSh version only; hostname, user, path and Git are opt-in modules; Git uses the known prompt branch (no command). Preset export never includes bytes and includes the asset path only on explicit opt-in; import is versioned, 32 KiB-bounded and rejects unknown fields. Transcripts never store the asset path; only the final portable still (or, if never painted, the layout without the path).
- Assets: absolute, cwd-relative and `~/` paths plus a local picker filtered to PNG/JPEG/WebP/GIF/APNG/.ans/.txt. Admission before decode: ≤8 MiB, ≤2,000,000 source pixels; GIF/APNG through the bounded decoder (#518: 75 frames, 32 MiB, 5 s). ANSI/ASCII ≤64 KiB, 40 rows, 240 columns, printable text + numeric SGR only. Originals are never modified; no persistent derived cache. External capture sanitization unchanged; one capture per provider, shared.
- One composition: `composeWelcome` (pure) drives the editor preview, startup and the P preview through `NativeWelcomePresentation`/`paintWelcome`; one `WelcomeSequencer` on the shared PresentationClock (≤5 s, ≤~30 repaints/s at startup); Reduced Motion / Effects Off / NO_COLOR give frame 0 with no subscription. Still-image effects are whole-image Portable treatments (no segmentation or invented motion).
- Startup playback never blocks the composer; input, resize, scroll, handover and shutdown stop it and release graphics by owner; a loading image says "Loading image…" and stores no still. P shows the current draft on NMSh's own alternate screen (no OS resize, no new session, no re-capture); any key closes it and is swallowed; draft and selection return unchanged.

## Native host fixes (2026-10-29)

- Host identity: one `terminalProfile()` for every surface. A terminal-specific `TERM` (`xterm-kitty`, `xterm-ghostty`) wins over `TERM_PROGRAM`. Cursor facts and `detectTerminalHost` use it. Inside tmux, the outer host's markers still name the host, as before.
- First run: `/cursor › Host native setup` in Kitty 0.49+ opens the Kitty studio even without the older include. Kitty below 0.49 keeps the built-in `cursor_trail` setup.
- A Kitty trail that is written must also be drawn. NMSh's own fragment sets `cursor_trail 3` when the effective value would otherwise be 0. This is judged without NMSh's own line, so later syncs keep it. A later line forcing 0 refuses. Confirming a trail sets `/cursor` Motion Off → Tail and Portable → Auto, and the review says so. Motion Off removes NMSh's trail, like a Portable renderer.
- Reload: after a confirmed write, a removal or a gate sync, NMSh sends Kitty's documented SIGUSR1 to `KITTY_PID`, but only when that process is one of NMSh's parents and its program is kitty. Otherwise it shows the reload keys. The review discloses this before writing. Ghostty is unchanged: it is never signalled, and L marks the reload.
- Host native chosen before setup: Portable draws, labelled "Portable fallback · <host> native is not set up yet". Before this, the cursor looked frozen. A host with no native effects keeps "Host native is not available".
- Previews: each trail style has its own shape (Blaze band, Lightning bolt and forks, Motion-blur ghosts, Comet taper, plain tail).
