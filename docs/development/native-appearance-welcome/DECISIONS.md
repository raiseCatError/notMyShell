# Architecture findings and recommended direction

No product architecture has been implemented or approved. Recommendations below follow the user's explicit specification and inspected code; implementation remains gated.

- Reuse PromptConfiguration and current canonical editors. AppearanceHub launches canonical editors, not copies. Extend cursor/native and existing host integration rather than create contradictory persistence.
- First repair existing Ghostty appearance: readGhosttySettings returns fabricated constants, saveGhosttySettings silently appends an include and overwrites a fragment. These cannot be reused unchanged for the requested safety contract. Reuse inspected Theme Bridge ownership/verified-edit patterns where applicable; further audit required.
- Host capability is separate from implemented NMSh presets and loaded-state evidence. Kitty's old backend exposes only tail; broadening it must accompany actual generator support and version/catalog checks, not capability advertising alone. Unknown versions fail closed for new features.
- Kitty pipeline compiler and Ghostty GLSL compiler share logical settings only. Validate composition, parameters and dependencies, preserve pre-existing shaders/includes, disclose unresolved effective values rather than invent defaults. Native adoption is explicit; native and Portable overlap must be suppressed, including pending reload state.
- Audit loaded-vs-written integration state. A written fragment does not prove a renderer loaded it. Switching Portable/reduced-motion cannot be claimed effective while old host shader remains loaded. Manual reload/restart status must remain visible and ambiguous overlap must not be painted twice. Further design needed for safely managing surface-wide native lifetime across fullscreen handover without per-event reload.
- NMSh already has a semantic Transition union, per-event look/timing, cancellation, deterministic paints and PresentationClock. Extend these, not an independent scheduler/event engine. Clean/Rich controls and Chroma palette remain canonical. Terminal-wide shader events are not NMSh widget events. Do not use BEL as a command-success channel (audible/unrelated side effects), magic pixel markers, remote arbitrary-window updates or per-event config rewrites.
- Use existing GraphicsService and ImageSurface typed builders/owner cleanup for welcome. External capture remains SGR-only; never forward captured APC/OSC/DCS/raw output. Current GIF is first-frame-only; animation requires bounded actual frame decode/composition, disposal/timing and native upload/control extensions. APNG support likewise is work, not a flag.
- Full-terminal P preview and startup share one welcome composition and sequencing service. Preview lifecycle acquires alternate screen/input, releases owned graphics on every exit and restores draft/selection. No session recreation or startup shell execution. Static final snapshot belongs to transcript; animation frames/bytes do not.
- Read Fastfetch JSONC as bounded data; never execute Neofetch shell config to discover logos. Only literal recognized assignments can be imported. Dynamic sources/includes require truthful unsupported guidance. Existing provider execution contract is distinct from safe new static system-info fields.
- New fields may use only explicit typed facts/static text, no automatic shell commands. Sensitive hostname/path/Git facts opt-in; presets omit private asset bytes/paths unless explicitly exported. Original assets are immutable.
- Proposed implementation bounds (builder decisions, not agreed): <=8MiB welcome asset input, <=2MP source, <=320x240 animation canvas, <=75frames, <=15fps, <=5seconds per startup playback, <=32MiB decoded animation data, bounded cache within existing GraphicsService budget. Validate both frame count and total bytes before allocating; unsupported/over-budget assets get deterministic still fallback or actionable refusal. Existing general viewer limits remain unchanged. No AI segmentation claims or new dependency without justified need.
- Independent PR slices required. Do not combine whole program into one feature PR. All required features remain in scope; unsupported native semantic targeting has production Portable fallback as explicitly requested.
